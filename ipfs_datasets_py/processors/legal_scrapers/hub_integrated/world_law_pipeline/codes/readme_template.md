# Place-code crosswalk (`world_law/pipeline/codes/`)

Maps our `place_id` (`wd:Q…` for non-US places, `gnis:N` for US places, `KG-kg_cbd:<organ id>` for Kyrgyz councils without a Wikidata item, as in
`global_municipalities_candidate.csv`, `place_additions.csv` and `world_law` staging) to national statistical / administrative
codes, so platform ids found by scrapers (CBS `gm0363`, TERYT, AGS, INSEE, JIS, IBGE, UBIGEO, …) can be
resolved to a `place_id`.

Generated by `build_place_codes.py` on {built_at}. Do not edit the outputs by hand.

Long-format columns: `place_id, country_code, code_system, code, wikidata_property, source, retrieved_at`
plus `is_current` (no end date on Wikidata), `wd_rank` (Normal/Preferred; deprecated values are dropped; if
an item has a preferred value only preferred values are kept), `valid_from`, `valid_to`, and `official_check`:
`match` · `match_code_name_differs` (code is in the official list but names differ, usually exonyms like
"Hamelin"/"Hameln, Stadt" or bilingual names; see conflicts.csv) · `not_in_official_list` · `name_match_only`
(code filled from the official list by unique name, not on Wikidata) · `not_municipal_level` (region/province
code) · empty (no official list loaded for that system).

## Successor table (`place_successors.csv`, EE + BE)
Columns `old_place_qid, old_name, old_code, dissolved_date, successor_place_id, successor_code, source, country_code,
successor_name, n_successors, note`. `successor_place_id` is always a place in the candidate list or in
`place_additions.csv`; chains (e.g. Toila vald -> Toila vald (2017) -> Jõhvi vald (2025), Komen -> Komen-Waasten ->
Comines-Warneton 57097) are followed to a code that is current in the official list. A municipality split between
several successors (2017 EE reform, e.g. Pajusi vald, Kohtla-Järve linn) has one row per successor and
`n_successors > 1`.

* **EE** (EHAK, 4 digits): Maa-amet `ADS_haldusreformi_EHAK_jargnevused` (2017 reform, sheet KOV_muudatused),
  EHAK 2026v1 (Statistics Estonia, via teabekeskus.tehik.ee; 78 municipalities, unchanged from 2025v5 which merged
  Jõhvi + Toila into Jõhvi vald 0250), Wikidata P1140/P576/P1366 chains for the 2005-2014 mergers (Kärdla linn,
  Kõue vald, Suure-Jaani linn, ...). Interim 2017 codes that EHAK later changed (e.g. Antsla 0142 -> 0145) are mapped by name.
* **BE** (NIS/INS, REFNIS): Statbel `TU_COM_REFNIS-20250101` (validity dates), the Statbel merger table for
  02/12/2024 (Bastogne + Bertogne) and 01/01/2025 (28 Flemish municipalities, e.g. De Pinte + Nazareth ->
  Nazareth-De Pinte 44086), the 2019 Hainaut renumbering table, the 2019 Flemish merger decree (Aalter, Deinze,
  Lievegem, Kruisem, Puurs-Sint-Amands, Oudsbergen, Pelt; checked against REFNIS start/end dates), the 1983 Antwerp
  merger, and REFNIS next-day codes for 1977-1987 changes. Out of scope: the 1977 fusion's deelgemeenten.
* Read-only test (`build_place_successors.py --test-unmatched`) against `staging/eu/_unmatched/`: see the report in
  the build notes; BE docs are matched by `issuing_body_name`, EE docs by `place_name`.

## Code systems (Wikidata properties verified 2026-10-10 via wbgetentities)

| `cz_ruian_obec` | CZ | P7606 Czech municipality ID (ČÚZK/RÚIAN) | 6 digits; equals the ZÚJ / LAU code for municipalities (no separate ZÚJ property exists on Wikidata) |

## Sources (in the order used)
1. **Cached Wikidata data in `/workspace/global_municipalities/`**: checked first. `wd/thin/*.jsonl`,
   `global_municipalities_candidate.csv` and `ref/` carry QIDs, names, ISO 3166-2, GeoNames and GNIS, but
   **no national-code properties**, so they give us the place list (QID per place) and not the codes.
2. **Wikidata statements in bulk**: one query per property against the QLever Wikidata endpoint
   (`{wikidata_source}`). That index is built from the dumps.wikimedia.org entity dump, so we got dump data
   without downloading the ~100+ GB JSON dump. `query.wikidata.org` was not used. Raw results are in `cache/wd_<P>.tsv`.
3. **Official lists** (cross-check, gap-fill by unique name, LAU/NUTS3 derivation):
{official_sources}
   Not loaded: the full GUS TERYT TERC file (eTERYT download is an ASP.NET form, and Eurostat's 2024 PL LAU codes
   are a 13-digit format that does not map to TERC; powiats are checked against the GUS BDL API instead), INEGI (gaia.inegi.org.mx timed out / TLS EOF from this box), SUBDERE
   CUT list (CL), BPS / Kemendagri lists (ID), CBS and Destatis files. NL, DE, HU, CZ and CH are checked
   through Eurostat LAU 2024 instead, because there the LAU code is the national code.
4. **Wikidata JSON dumps**: not downloaded. Disk is 59 GB free against a 100+ GB dump, and streaming would
   take hours. QLever already serves the same dump (2026-08-10 + live updates).

## Refresh
```bash
cd /workspace/world_law/pipeline/codes
# 1. official lists (optional; URLs in coverage.json -> official_sources); Eurostat LAU xlsx is split into
#    cache/eurostat_lau_2024_<CC>.csv by the snippet in this README's history / build notes
# 2. Wikidata values (re-queries QLever, ~1 min):
/workspace/hf-venv/bin/python build_place_additions.py --refresh   # PL powiats, NL water boards, Frisian munis, CA CSDs (StatCan + P3012)
PYTHONPATH=<dir with openpyxl> /workspace/hf-venv/bin/python build_place_codes.py --refresh
# without --refresh the cached cache/wd_<P>.tsv are reused
```
`openpyxl` isn't in hf-venv. Install it into a scratch dir and point PYTHONPATH there:
`uv pip install --target /tmp/pylib openpyxl`. Without openpyxl, the soumu, INE and INEI xlsx checks are skipped.
