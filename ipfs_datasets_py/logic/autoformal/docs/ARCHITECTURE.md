# Architecture and owner map

The maintained pipeline uses one implementation owner per stage. The [work catalog](work_catalog.json) records canonical owners and selected evidence; it is the maintained machine-readable index for this map. Imports below are relative to `ipfs_datasets_py.logic.autoformal` unless stated otherwise. The existing compiler and legal IR remain outside this package where already owned; adding a new wrapper does not replace them.

```mermaid
flowchart LR
  S[Versioned law source] --> I[Source/span/entity correspondence]
  I --> C[Complete source and context evidence]
  C --> D[Scoped definitions and norms]
  D --> R[Interpretation and every-use review]
  R --> G[Dependency graph component]
  G --> P[Conditional Lean preparation]
  P --> N[Owned full native build and receipts]
  N --> U[Shared incremental corpus]
  R --> T[Reviewed grouped targets]
  I --> V[Declared 8D 384D 768D 4096D inputs]
  T --> M[Controlled learning and model evaluation]
  V --> M
  M -. proposals require review .-> R
```

Corpus construction and model promotion have separate gates. Reviewed manual or compiler-produced typed targets can proceed through graph and Lean owners while learning is evaluated independently. Model-produced candidates enter the same source, meaning and applicability review; model quality alone grants no corpus admission.
