# Source-to-typed norm correspondence proposals

`legal_source_typed_norm_join_v1` joins the existing complete sampled-source scope report to an optional existing typed relational candidate. It is a separate correspondence envelope. The source/scope and typed/native owners retain their original contracts; the relational request still has `source_binding: null`.

The join validates both reports against their independent canonical hashes and original replay inputs. Exact request-file bytes have separate hashes from canonical JSON commitments. Its exhaustive typed-node ledger references the source scope's existing anchor paths or records an explicit introduced unresolved assumption. It never interprets the lexical text automatically.

Producer paths come from the existing owners' actual module closure. Offered report maps must equal those trusted maps before their keys can influence file reads. The join checks producer identities before, between and after owner replay, and after output serialization. These checks preserve the current prior-owner implementations and do not accept arbitrary producer filenames from a resealed report.

Use `prepare_source_typed_norm_join_v1(scope_report, relational_report, join_request_raw, ...)`, `source_typed_norm_join_sha256(report)` and `validate_source_typed_norm_join_v1(report, scope_report, relational_report, join_request_raw, expected_report_sha256=..., ...)`. Preparation requires `expected_join_request_sha256`, `expected_scope_report_sha256`, `expected_relational_report_sha256`, `scope_replay_inputs`, `relational_request_raw` and `expected_relational_request_sha256`. The scope replay inputs contain its complete sampler, raw HTML, original scope request/declaration bytes and all independent source/sampler/request commitments. Expected hashes must come from the original retained manifests, not newly substituted inputs.

The caller's request is closed JSON:

```python
{
    "schema": "legal-source-typed-norm-join-request/v1",
    "interpretation_status": "unreviewed_correspondence_proposal",
    "component_id": "declared-connected-component",
    "alternative_id": "explicit-hypothesis",
    "selected_unit_ref": exact_original_sealed_unit_reference,
    "node_correspondences": [
        {
            "typed_path": exact_existing_structural_mapping_path,
            "source_anchor_paths": [exact_existing_scope_anchor_path],
            "disposition": "lexical_hypothesis",
            "unresolved_codes": [retained_source_or_introduced_issue_code],
            "rationale": "Caller explanation of the proposed correspondence",
        },
    ],
    "introduced_unresolved": [
        {
            "code": "explicit_new_assumption",
            "rationale": "Missing formal identity, domain or interpretation",
            "affected_typed_paths": [exact_existing_structural_mapping_path],
        },
    ],
}
```

Every typed structural-mapping path must appear exactly once. Unknown paths cannot impersonate a predicate, argument, binder or modal operator. The owner derives node identity/kind, predicate argument index and declared role, variable name and its lexical binding quantifier, and modal/connective placement from the validated typed expression. The original scope anchors supply exact local and document character/UTF8 geometry. An anchor proves custody of the phrase; it does not prove that the phrase denotes the proposed variable, predicate or logical operator.

Nodes with no source anchor require an introduced unresolved issue that explicitly names the affected path. All introduced issues must be used. Original source unresolved issues are retained unchanged. Quantifier/domain choices, introduced entities, unresolved passive roles and incomplete relation structure cannot become hidden defaults or disappear from the result. The six original context requirements are not an exhaustive dependency inventory.

The explicit source-only pending state has `relational_report`, its expected hash, relational request bytes and request hash all null, with empty node and introduced-issue lists. It preserves the entire source scope and original unresolved issues without manufacturing a typed target. This supports source material outside the relational profile, including unsupported numerical, purpose or anaphora constructs.

The result supplies a custody-linked **partial hypothesis**, its typed candidate and provenance ledger. Full statutory `formal_norm_ast`, lowered IR, native output for source, graph, lookup and governing-use outputs remain absent. The independently validated relational syntax report can retain generated Lean text as authored syntax evidence; that text is not promoted into a source output by this join. Actual reviews, accepted meanings, signatures, admission authority and training/evaluation masks remain false/zero.

The [retained pilot](../../../../../../../artifacts/legal-corpus-source-typed-join-20261015-01/README.md) associates two competing partial hypotheses with the same §7213 paragraph while preserving its passive-role, direction, approval, plural and applicability issues. §7214 remains source-only pending. The organizer/team has seen the hypotheses; they are not blind targets, learned outputs or independent evaluation samples. Actual statutory meaning selection and native builds remain later gates.

## Explicit counted-frame correspondence v2

The additive counted-only entry points live in this same owner. V1 retains its
relational and source-only contracts. Its retained pilot's source-only §7214
state remains historical evidence; the new API does not reinterpret that pilot.

Use `prepare_source_typed_norm_join_v2(scope_report, counted_report,
join_request_raw, ...)` and `validate_source_typed_norm_join_v2(report,
scope_report, counted_report, join_request_raw, expected_report_sha256=..., ...)`.
Both use `source_typed_norm_join_sha256` for complete report identity. Preparation
requires `expected_join_request_sha256`, `expected_scope_report_sha256`,
`expected_counted_report_sha256`, `scope_replay_inputs`, `counted_request_raw`
and `expected_counted_request_sha256`. Every counted input is required; v2 has
no null-input, relational fallback or implicit source-only mode.

V2 requests use `legal-source-typed-norm-join-request/v2` and the same seven
request fields shown above. Their status remains
`unreviewed_correspondence_proposal`. Source anchor paths and issue declarations
must cover the complete new typed domain: 49 nodes plus six binder rows. Each
quantifier is followed by its binder, then its body. The owner compares the node
and binder projections with both original counted ledgers in exact order. It
derives all four `Member` occurrences with ordered object/event/time roles, all
six built-in equality occurrences with ordered left/right endpoints, and all
24 variable occurrences with their precise lexical binding and predicate or
equality context. It supplies no `native_path` for the counted owner's
specialized generated-text renderer.

The existing [authored counted-frame owner](legal_counted_frame_v1.md) is fully
replayed from its original independently pinned request and complete report.
V2 retains that report as `counted_frame_report`, including its original
assumptions and nonexecuting preparation receipt. A detached typed candidate
retains the fixed frame, membership relation, identity pairs, counts and all
assumptions. The join neither changes the counted owner's source-unbound
contract nor borrows a separate native build as a source-meaning proof.

The v2 result has schema `legal-source-typed-norm-join-proposal/v2` and profile
`whole-source-partial-counted-frame-correspondence/v1`. It records only an
unreviewed partial counted-frame hypothesis. Source custody, original unresolved
issues and context remain intact; counting scope, legal object identity,
participants, modality, duties, governing definition and applicability remain
unresolved. The counted clause does not by itself represent the complete
statutory norm. Formal norm, lowering, native output for source, graph and
review/admission outputs remain null or false; training/evaluation masks remain
integer zero. No model, training or native process executes in either join API.
