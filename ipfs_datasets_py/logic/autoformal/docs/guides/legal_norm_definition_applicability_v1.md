# Record exact use definition applicability declarations

`legal_norm_definition_applicability_v1` prepares and authenticates a separate
applicability statement over the existing
[norm-definition evidence companion](legal_norm_definition_evidence_v1.md).
It binds one nominated typed occurrence to one supplied definition alternative
without applying a definition, rewriting an AST or admitting a semantic graph.
All competing alternatives remain visible.

The public entry points are `build_norm_definition_applicability_template_v1`,
`build_norm_definition_applicability_declaration_v1`,
`assess_norm_definition_applicability_v1` and
`validate_norm_definition_applicability_v1`.
`norm_definition_applicability_sha256` commits the complete report.
Validation takes the original assessment arguments and an independently retained
complete-report pin, then regenerates the result.

## Replay the complete association evidence

Supply the complete companion, an independent full-companion canonical pin and
all original arguments accepted by `prepare_norm_definition_evidence_v1`.
The owner regenerates the norm preparation, each contextual definition
correspondence and every supplied original definition assessment. Original
subjects, clocks, source generations and manifests retain their identities.
Rehashing a modified report cannot replace that replay.

Supply the original norm review subject and dependency manifest with independent
subject and manifest pins. The manifest pin is the existing validated embedded
payload digest, distinct from a hash of the complete serialized manifest.
The subject is regenerated from the companion's
complete norm inputs. The new action uses that unchanged subject, while the
common declaration commits the whole companion and every ordered use, link,
alternative and original norm obligation. The norm manifest covers its original
norm dependency population; it does not silently acquire the definition
endpoints' dependencies.

Uses are grouped by the complete typed target record in first-appearance order.
Equal symbol names or a matching path in another expression cannot merge them.
Each group retains all its ordered exact link references, inverse source paths,
source anchors, typed node, binder/argument/modal context and definition
nominations. Completeness means the supplied nominated population. The companion
does not enumerate every term or every possible governing definition.

## Make an explicit statement for each nominated use

A submitted declaration supplies one ordered decision for every use. The first
profile permits two decisions:

- `declare_one_supplied_alternative_applicable` selects one exact existing link
  belonging to that occurrence. It requires a canonical civil legal-as-of date,
  an authored scope statement, a rationale and independent supporting evidence.
- `unresolved` keeps the selected link null. Alternatives and uncertainty remain
  retained; no candidate is selected implicitly.

The blank template has null decisions, dates, statements and declaration time.
It is an unsubmitted handoff, not a finding that every use is unresolved.
Unselected alternatives are not declared inapplicable. Selection supplies no
priority rule, exhaustive search, multiple-definition composition, relation-arity
or sort compatibility. Those need separate evidence and supported profiles.

Legal-as-of is distinct from source edition, signature time and evaluation time.
The API checks date syntax and existence in the civil calendar. It does not
establish effective/repeal windows or the asserted scope's legal meaning.
Supporting references identify exact supplied bytes. They do not establish the
truth or adequacy of the support, or recursively authenticate nested evidence.

The assessor preserves each original definition assessment and independently
rechecks it at the explicit applicability evaluation time. It uses the same
originally pinned registry, policy and complete source-claim population, plus
explicit current observations for that endpoint's original manifest. The exact
ordered context population and supplied evidence references must also pass
intake; a valid signature alone cannot repair missing or changed context.
Deliberately open context and dissent remain pending evidence. Missing
assessments remain absent and block endpoint-review prerequisites. Known expiry
and already-declared revocations can activate; the API does not discover unseen
registry generations or authenticate the supplied clock.

Current norm dependencies are checked separately. No fabricated union manifest
or changed source registry substitutes for the originals bound by signatures.
A declaration cannot precede the original considered assessments or source
claims, or follow its authorizing claims or supplied evaluation time.

The exclusion inventory includes every supplied definition-review claim,
including rejected and unknown-key claims. It retains claimed and registered
principals and DIDs and known registered public-key bytes. Unknown source keys
block complete cryptographic inventory. Contextual unsigned declarations also
contribute their claimed principals; opaque identity references cannot supply

blockers. Legal and formal association reviewers must use distinct declared
principals, key IDs, DIDs and public keys and avoid the supplied source actors.

Norm-content review actors are not inputs to this profile. Its checks do not
establish a complete norm-review or global cohort, human independence or reviewer
competence. Combining these custody records with substantive norm and definition
