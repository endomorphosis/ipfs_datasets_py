# Bounded compact-content generation and batch binding

This coordinator continues an explicit supplied prefix using the existing
`legal_compact_content_head_v1` numerical head. The head already calls the
qualified finite-score selector; the coordinator does not call a second
selector, introduce another grammar or construct a source encoder.

The canonical module is
`ipfs_datasets_py.logic.formalization.autoencoder.legal_compact_content_generation_v1`.
Its report schema is `legal-compact-content-generation/v1`, with profile
`bounded-conditioning-compact-content-generation/v1`.

At authoring, the numerical producer is separately source-reviewed and installed;
joint runtime qualification is pending. This increment enrolls its 87 actual head
cases together with 38 generation cases and 220 existing regressions in one owned
345-case cohort. It assumes no previously qualified numerical head. Earlier
collection and admission refusals grant no passing-test credit. The exact saved
owned-run evidence determines subsequent runtime status.

## Inputs and continuation

`generate_compact_content_v1(checkpoint, conditioning, prefix_ids, context_raw,
*, expected_checkpoint_sha256, expected_context_sha256, max_new_tokens,
prefix_origin, context_origin)` accepts the original checkpoint, a plain finite
384-coordinate conditioning vector, nonempty supplied IDs, and independently
committed context bytes. The head validates its closed checkpoint, ordered
537-entry codec, weights and CPU float32 profile through the actual public score
call. No redundant checkpoint restoration precedes a terminal no-forward call.

`max_new_tokens` is a plain integer from 1 through 512. Actual total length,
including the entire supplied prefix and BOS/EOS, never exceeds 512. The caller's
new-token allowance does not override the token owner's total output ceiling.
All requested data and complete results are bounded; an overflow raises instead
of omitting steps, dropping rows or repairing an EOS.

Prefix origins are `bos_seed`, `authored_fixture`, `target_derived_label`, and
`caller_supplied_unverified`. `bos_seed` requires exactly `[1]`. Context origins
are the existing CONTENT batch declarations: `authored_fixture`,
`target_derived_label`, or `caller_supplied_unverified`. An origin string supplies
no authentication or inference permission.

Each numerical step receives the current full selected prefix. Every complete
head score report remains in `trace`, including its 537 scores, score commitment,
checkpoint/state/conditioning commitments, public prefix report, raw argmax and
constrained selected decision. Public token-prefix checking immediately after a
selected token recognizes completion or a blocked prefix. A selected EOS does
not trigger an unnecessary additional head forward. Final IDs always pass the
existing public token decoder without a reference tree or identity sidecar.

The generator retains `initial_prefix_ids` separately from
`selected_token_ids`. `generated_ids` is their concatenation and is the complete
prefix offered to final decoding. It must not be described as a sequence whose
every token was generated by the model. `raw_argmax_ids_by_step` records the raw
maxima evaluated **along the constrained selected prefixes**. It is not a second,
independently autoregressed unconstrained output path.

## Results and terminal states

| Status | Meaning |
| --- | --- |
| `complete` | A selected continuation completed a valid candidate. |
| `supplied_complete` | The initial prefix was already complete; zero tokens were emitted and its head report records `no_forward`. |
| `blocked` | The existing public prefix owner supplied no admissible continuation, including rejected or total-budget-exhausted prefixes. |
| `step_budget_exhausted` | The requested number of new decisions was used before completion; final decoding remains an incomplete observation. |

`reason` is null on new completion, `supplied_prefix_already_complete` for an
already complete seed, `max_new_tokens_reached` for a step limit, and the public
prefix reason/status for blocking. `final_prefix_report` and `final_decoding`
retain the actual lower-level classifications. No new invalid-UTF8 outcome is
invented for the fixed lexical vocabulary.

`score_call_count`, `numerical_forward_count`, `emitted_token_count`, and
`total_token_count` are separate. A supplied complete/blocked prefix has a
no-forward score observation but no emitted decision. `model_executed` reports
whether a genuine numerical forward occurred in this generation call;
`training_executed` and `compact_optimizer_executed` are false. This is an
engineering execution fact, not source fidelity or legal authority. A separately
authored head regression may train a fictional old-grammar donor; that workload
is outside these generation facts and requires its own qualification disclosure.

The report includes full conditioning and its canonical commitment, checkpoint
and weights commitments, ordered codec commitment, raw and canonical context
commitments, settings and their commitment, complete traces, final decoding and
finite source descriptors. Caller conditioning and its float32 conversion remain
distinct within each head report. Symbolic context constrains the selector and
does not enter the GRU as a source embedding.

## Original-bound validation and source custody

`compact_content_generation_sha256(report)` provides bounded closed-report
identity. It grants no authority and imports no numerical operation owners.

`validate_compact_content_generation_v1(report, checkpoint, conditioning,
prefix_ids, context_raw, *, expected_report_sha256, ...same generation keywords)`
first requires an independent report commitment, then regenerates the complete
report from those original inputs and requires canonical byte equality. This is
actual numerical replay; callers must use the existing admitted CPU resource
scope and the head's one-Torch-thread requirement. Input and producer errors,
interrupts and whole-bound failures propagate without partial reports.

The coordinator fences its own code and exact reviewed head, token, selector,
batch, compact-content, numerical-body and transfer sources before imports and
through final serialization. Imported public owner origins are checked.
Complete returned head producer descriptors and the token owner's exact two
descriptors, sizes, authority and masks are checked against that fixed closure.
Caller-supplied paths never authorize reads. The public head and existing owners
retain their own transitive source checks; the native qualifier independently
records its finite checked-source execution closure. These checks are not a
hermetic Python or third-party Torch binary proof.

The report allowance is 64 MiB, input allowance 96 MiB, with eight million JSON items
and depth 96. Canonical UTF8/JSON escaping and punctuation are charged before
serialization; NUL, surrogates, cycles, nonfinite values and nonordinary objects
are refused. These bounds allow complete 537-score traces throughout the declared
512-ID output profile. Tests and diagnostics should use short bounded engineering
controls and preserve the existing native storage reservation.

## Existing CONTENT batch adapter

`prepare_compact_content_generation_batch_prediction_v1(report, checkpoint,
conditioning, prefix_ids, context_raw, population_raw, *,
expected_generation_sha256, expected_population_sha256, occurrence_id,
...same generation keywords)` fully replays the generation before forming one
closed existing CONTENT prediction row. The selected occurrence's raw source
and model-context identities come from the independently pinned **whole**
population transport. They remain caller declarations, separate from the
signature/ordered-role context used for decoding.

The wrapper schema is `legal-compact-content-generation-batch-prediction/v1`,
profile `verified-trace-to-declared-content-observation/v1`. It includes
`prediction_row`, the actual existing `predictions` envelope,
`population_sha256`, and an explicit `generation_report_sha256` link
(`generation_sha256` is the same commitment). It introduces no batch denominator
or new metric. A one-row envelope for a larger population leaves all other
occurrences missing under the existing evaluator. The adapter checks the selected
closed row and transport commitment; the existing batch owner remains responsible
for complete population/reference validation and accounting.

The envelope deliberately declares `kind="decoder_declared"`, dimension 384 and
the actual checkpoint SHA, with `encoder_sha256=null`. This profile has no source
encoder to commit. The existing evaluator therefore reports
`generation_decoder_encoder_invalid` and withholds comparison credit even when
the continued candidate is valid. No conditioning-vector hash is substituted for
an encoder hash. Batch validation does not automatically authenticate the linked
generation trace; the separately replayed wrapper records that boundary.

Any initial prefix other than `[1]` is conservatively prefix-assisted and sets
`teacher_forcing=true`. A target-derived prefix or context sets
`target_access=true`. These flags reach both generation declaration and raw
prediction row. A near-complete exposed target prefix followed by a genuine EOS
decision qualifies mechanical continuation only. It does not become a complete
source-generated success or eligible held-out example. All permissions remain
unverified for caller-supplied vectors and contexts, even when flags are false.

## Token efficiency and remaining gates

Full numerical/logic traces belong in indexed artifacts with content hashes,
where DuckDB/DuckLake metadata can link checkpoint, source generation, context,
prefix, scores and final output. They should not be copied wholesale into the
agent supervisor prompt. Later permitted-context semantic capsules can retrieve
bounded, relevant evidence while preserving those links.

The 537-entry vocabulary and compact lexical lengths do not establish provider
token savings. That claim requires actual tokenizer measurements and a matched
task/population A/B evaluation, including context, receipts, failures and all
other token costs. This coordinator supplies no verified source encoder,
statutory/cache occurrence join, governing interpretation, context permission,
exposure/split eligibility, optimizer consumer, convergence proof, accepted graph
or Lean admission. Training/evaluation masks remain 0 and authority flags false.

The earlier unlaunched SEMANTIC batch proposal and its 76 staged tests remain
historical unexecuted material. This increment uses the qualified existing
per-observation CONTENT route; complete context availability/inventory is a
separate future versioned gate.
