# Retained open-vocabulary pointer decoder on new native-cache sources

The opt-in `arbitrary_native_span_runtime` connects the new source-bound raw
GTE384 cache to the existing warm-start source-span decoder. It preserves the
continuation lineage and restores the selected October 2 raw384/source-only
checkpoints; it creates no new neural architecture or checkpoint. Pure
preparation verifies source occurrences, raw-vector receipts, a pinned historical
recipe compatibility audit and current source owners before numerical opening.
Raw vectors cannot be passed off as `core384` or `trained384` projections.

The same eight exposed US Code spans from the previous native-cache pilot run
through both retained checkpoints under none, zero, disabled and rotate controls.
Rotation uses the original occurrence order before source preflight filtering.
Source warnings, missing eligibility, abstentions and candidate facet intervals
remain explicit. The cached paragraph vector is used; clause vectors and full
document context are not model inputs. This run performs zero encoder calls,
zero optimizer updates and no checkpoint or recipe selection.

The decoder can represent one flat O/P/F rule with one exact copied span per
facet. It cannot express definitions, multiple rules, paraphrases, multiple
values within a qualifier facet or variable binding. A future training cohort must first receive
independent source-context review and an explicit representability disposition.
Keep weak/generated labels separate from reviewed targets and keep the eight
development spans outside any claimed independent confirmation split. Evaluate
facet roles, modality, qualifier preservation, contradictions and calibrated
abstention before selecting a new checkpoint. Reuse these pointer heads with
the structural decoder's grammar constraints only under a distinct audited
readout/training lineage; never repair a failed output and score it as raw output.

## What the comparison exposes

Each checkpoint/control lane found all eight source rows eligible for this narrow
runtime profile, produced one canonical source-copied proposal and refused seven
outputs because their copied facets overlap. The sole proposal is on 1 U.S.C.
106: the raw384 checkpoint selects actor `as the`, action `called`, object
`the enrolled bill, or`, and condition
`the presiding officers of both Houses and`. The source-only checkpoint selects
actor `as the case` and the same other fragments. These are model proposals,
not reviewed role annotations. Exact copying and canonical grammar do not
establish correct statutory meaning.

For both checkpoints, zeroing, disabling or rotating the raw context leaves the
eight final proposal/refusal decisions and copied facet anchors unchanged.
Raw384 scores do change under these controls; source-only scores stay unchanged.
This evidence does not establish that the raw context is ignored, or that it
improves legal interpretation. Both lanes need reviewed actor/action/attachment
supervision and compatible facet selection before an accuracy claim is possible.

The successful attempt restores both models without an encoder call or optimizer
update. Its sampled process-group RSS peak was 687,083,520 bytes, with eight
model-phase samples and 7.53 seconds from model gate to reap. These measurements
exclude the guardian's wider 51.75-second accounting/admission run and are not
continuous or kernel-enforced limits. Failed attempt 01 acquired a reservation
that remains retained after its import failure; attempt 02 was rejected before
acquiring a reservation or launching a child. Attempt 03 released only its own
reservation. Prior and foreign claims remain unchanged at the inspected endpoints.

## Next training work

1. Create a physical-source and context review workflow with independent role,
   modality, qualifier and representability annotations. Preserve unanswered
   targets and record disagreement; the current authored-only review format
   cannot admit these statutory cases.
2. Build a fresh source-section/family grouped corpus with documented duplicate
   and exposure closure. Keep the eight already exposed cases as development
   regressions. Fit and tune on designated groups before opening confirmation.
3. Compare independent pointer heads, joint compatible span selection, typed
   grammar constraints and their combination. Retain the original failed
   proposals, score each ablation separately, and measure reviewed role fidelity
   and calibrated abstention as well as syntax and copying.
4. Extend each producer/decoder identity separately: 8D, raw384, core384,
   trained384 and 768D are distinct representations. Add supported logic-family
   lowering and execute the pinned Lean `lake build legal` gate on exact outputs.
   Compiler success and source-meaning fidelity remain separate results.
