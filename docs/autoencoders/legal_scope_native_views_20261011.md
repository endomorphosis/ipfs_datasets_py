# Statutory scope bindings and saved native parser views

This contribution closes two transport gaps between saved decoder proposals, declared source scope and native logic parsers. It does not create statutory semantic targets or establish decoder accuracy.

`statutory_scope_declaration_binding` joins existing archived review declarations to caller-supplied canonical statement scope. It retains the exact packet, submission, declaration, physical source, selected interval and complete context identities. Ordered rule, modality, qualifier, anchor and attachment maps preserve repeated literals and shared attachments. Existing scope validators check connective and binder structure. Review completeness, disputes, unresolved meanings and geometry inconsistencies remain separate from successful transport. An archived trigger list has no rule association; that linkage remains unassessed.

Use `prepare_binding_slots` to obtain unanswered slots, `bind_scope_declarations` with explicit sidecars, and `validate_binding` to replay the original inputs. There is no inferred scope, cue, qualifier meaning, alias, reference resolution, target or admission. All training and evaluation masks remain zero. A complete physical context exceeding the existing scope profile is a recorded limit; it is never truncated or relabeled as unnecessary.

`saved_span_native_views.prepare_native_view` first validates the unchanged saved-span deontic adapter, then sends its exact source-bound request to the existing native bridge. The explicit selector is `native_parser_profile="tdfol"` or `"dcec"`. The sealed legal family remains `deontic`, and `registry_family_qualified` stays false. Each parser must independently preserve its full AST and reconstruct the original canonical IR, interpretation and occurrence bindings. DCEC object functions and TDFOL constants have different AST representations; the boundary does not assert equality between them.

| Native parser view | Supported subset | Refusals retained |
| --- | --- | --- |
| TDFOL | Ground O/P/F with existing declared Boolean condition and exception trees | Temporal facets, quantifiers, free variables, agents and modal contexts |
| DCEC | Ground O/P/F without qualifiers | All qualifiers, temporal facets, cognition, events and fluents |

Nested native-bridge family labels remain unchanged, and describe the bounded parser view. They do not qualify the registered temporal-first-order route or the DCEC alias of the event-calculus route. No old route, emitter, decoder, calendar gate, native parser or compiler envelope changes.

For a supported view, pass its original `request` plus `family=view["native_parser_profile"]` to `legal_source_family_lake`. Preparation is not a build; actual validation requires the existing `lake build legal` gate. Unsupported rows block the entire supplied batch, so record their dispositions before assembling a supported batch. A build checks generated syntax and module coverage; it does not verify statutory interpretation, legal truth, semantic equivalence or proof authority.

The pilot uses a previously trained source-only decoder configured with `latent_dimension=384` and `latent_enabled=False`. It performs no encoder calls, inference, fitting or optimizer updates. This is not a zero-dimensional model and does not evaluate the 8D or 768D latent decoders. The complete previously exposed 96-row authored tuning report remains bound; the 12 selected rows are engineering examples with explicit fictional declarations, not held-out statutory gold.

All 24 row/profile attempts remain in the denominator. Preparation produced nine TDFOL views and three plain DCEC views. Six temporal attempts and six DCEC qualifier attempts retain explicit refusals. Actual US Code retains all eight physical items and both saved lanes (16 dispositions); no unfilled declaration is silently completed.

Saved diagnostics show why temporal syntax alone is insufficient: two real joint predictions assign “civilian law enforcement official under this” and “weapon of” to the temporal field. One also assigns an em dash to the action field. Three separate authored deadline predictions have copied source slices exactly matching “within 1201 days”. These are distinct diagnostics; neither establishes statutory semantic fidelity. Relaxing the compiler profile would not establish correct roles for these unreviewed, suspected misclassifications. Old unmerged deadline/event patches are preserved recovery evidence and are not claimed as APIs in the committed baseline.

## Next accuracy work

1. Collect independent review of source roles, modality cues, qualifier attachments, connective scope, binders, definitions, cross-references and time origins. Preserve full source custody and dissent. Split legal sections and related provisions before annotation-derived training; identify prior exposure explicitly.
2. Introduce a reviewed context strategy for the three oversized complete sections. Any windowing needs explicit coverage and source provenance and a separately versioned contract; it cannot be hidden in this bounded profile.
3. Reconcile existing event/deadline branch implementations against committed owners before adopting code. Require exact duration/calendar declarations, physical span custody and negative controls for spurious temporal fragments. Keep duration parsing, clock interpretation, temporal operators and event-family qualification separate.
4. Compare the existing latent and source/span architectures under matched data, decoder capacity, seed, update budget and legal-section splits. Report 8D/384D/768D separately. Test source-only, latent-only, joint, shuffled-latent and zero-latent controls; include alternate-latent donor tests to detect source memorization and latent dependence.
5. Train on qualified targets only after the existing admission owners authorize them. Score exact role/span fidelity, modality, qualifier order and scope, reference resolution and semantic preservation separately from parser acceptance and Lake build rate. Add cue and scope counterfactuals; include abstention and unsupported-family rates with full denominators.
6. Promote weights only when independent statutory evaluation improves without regressions in support and refusals. Publish checkpoint lineage, exposure/splits, family/profile coverage and all failed comparisons alongside weights. Existing Hub weights remain available; this contribution produces no weights or default-model promotion.

The selected eleven-suite run passed 744 tests with two native opt-in skips. The actual eight-item scope replay remains pending with zero submissions, sidecars and semantic labels; three full contexts have 21,347, 28,500 and 71,688 characters and retain profile-limit dispositions. The separate actual `lake build legal` gate passed all twelve parser requests and covered all fourteen expected Lean modules; workspace cleanup and binary pins passed. The earlier nine-request deontic build remains separate prior evidence. No model, encoder, fitting or optimizer call ran in this contribution. Namespace-isolated tests do not qualify top-level plugin initialization. Native RSS and workspace guards are sampled checks, not kernel aggregate quotas; native child networking is not audited by the Python driver.
