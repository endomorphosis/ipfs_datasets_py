# Legacy CUDA memory backpressure

The continuous US Code census waits on valid low-free CUDA memory observations. Operating checks retain the 2 GiB safety reserve; initial device/allocator admission still requires the unchanged 2 GiB budget plus 2 GiB reserve, less any already reserved allocator bytes. The actual owning process reads CUDA free memory. Linux MemAvailable and NVIDIA-smi memory values are not substitutes, especially on a unified-memory GB10.

Only `CudaHeadroomPressure` is temporary. Its pickle-safe observation preserves the actual free, total, allocated and reserved bytes, required free bytes, stage and timestamp. Unknown or inconsistent telemetry, an excessive allocator, invalid capacity, lost lock/ownership, source drift and model errors remain fatal. A failed sample is retained in `CudaDeviceBudget.last_observation` before the typed error is raised.

The worker probes every two seconds during a pressure wait, with no model evaluation between failed checks. It atomically replaces `runtime/cuda-headroom.json` and emits a journal event on the first failure, every thirty seconds, and after recovery. This file is a sampled resource observation, not a proof or global GPU reservation. Match its PID and timestamps to the current owner generation; an old ready record does not establish readiness after a restart. Each recorded pause rechecks the full canonical package identity and runner before returning to work. There is no campaign-wide productive timeout.

The existing outer owner continues native lease heartbeats, runtime/RSS checks and periodic exact disk accounting while the CUDA future waits. The engine keeps its bounded single prefetched CPU batch; only the engine writes its DuckDB queue. Controller cancellation stops and reaps the original process group, including waiting workers. A wait after evaluation preserves that result and does not rerun the model; publication occurs only after headroom returns. Per-batch `cuda_headroom_waits` and `timings.cuda_headroom_wait_seconds` distinguish backpressure from model/bridge processing time. The normal healthy path performs no extra package scan or headroom-state write per check.

If a worker failed before staging its result, leave its queue rows and history intact. After explicit stopped-owner durability and claim reconciliation, the existing queue recovery returns unfinished batches without durable receipts to pending. Previously published spans remain done. Restart only once after a fresh real resource grant and producer binding; do not enable a failure loop that accumulates retained reservations.

The 160 GB campaign cap, 50 GB per-worker ceiling, native CPU/RAM policy, physical filesystem watermark, five bridge names, prover/cache settings and checkpoint identities are unchanged. This is legacy mock-8D inference with the real compiler and diagnostic model guidance; it does not train the model or establish semantic qualification. Only `lake build <Lib>` admits Lean; resource readiness, loss values, compiled rules and uploads do not. The Constitution remains unformalized.
