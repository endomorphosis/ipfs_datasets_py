# Decoder end-to-end checks — 2026-10-01

Local training, fresh-process resume, DuckDB registration, decoding, generated Lean
schema builds, and census/goal export work in the tested paths. These results do
**not** establish semantic qualification or distributed readiness. The legal
decoder still loses one held-out exception, and the new formula runtimes still
need production census/fleet/Hub adapters.

The [machine-readable summary](../implementation/reports/evidence/decoder-e2e-20261001/summary.json)
and [hashed evidence manifest](../implementation/reports/evidence/decoder-e2e-20261001/manifest.json)
retain the observations, exact formal outputs, generated Lean inputs/logs, and
test harnesses. They contain no checkpoint weights. Serialized receipts are
audit evidence; only a fresh verified execution establishes runtime trust.

## Logical outputs and their limits

The held-out clause

> The officer shall retain the file for at least 20 days unless emergency.

produced this source-only learned output:

```json
{"rules":[{"action":"retain","actor":"officer","conditions":[],"exceptions":[],"modality":"O","object":"the file","temporal":["at least 20 days"]}]}
```

The expected `exceptions` is `["emergency"]`. Its display form is
`O(retain(officer, "the file")) scope={"temporal": ["at least 20 days"]}`;
the complete AST is authoritative. The direct compiler retained the emergency
exception in the fresh census test. This is a real model error, even though the
generated structural schema passes Lake. All model qualification/admission
flags remain false.

The three requested compiler gates passed, with parser-supplied string atoms:
the within-10-days obligation retains its emergency exception; the disclosure
clause is a prohibition; the minimum-duration clause retains `at least 20 days`.
All three empty-vocabulary calls still abstain. Restricted syntax checks passed
for all eight legal family fragments on these gates (24 checks). These checks
do not establish unrestricted family semantics.

The numeric route separately executed **`lake build Legal`**, with its source
lock intact. Its theorem checks the 19/20 boundary of a minimum-duration
threshold. This is admission of that numeric pattern only. `within_duration`
still produces no renderable threshold. The Constitution remains unformalized.

Expanded native routes exercised:

- Intent: action/Hoare, facts, intentions, norms, safety, workflow/temporal.
  The verification-condition-role projection has no declared logic family and
  is explicitly excluded in the report.
- UI/UX: frame logic, event calculus, temporal-deontic FOL, DCEC.
- Security: program, contract, transition, temporal, heap, separation,
  hyperproperty. TLA+ compilation is retained, but TLC was not run.

Native decoding reconstructs fixed-shape, training-vocabulary typed inputs;
these runs are not independent raw-text-to-logic tests. The generated Lean
structures check the exact output shape and instance. They do not prove source
semantics or execute each family's backend. Out-of-vocabulary input was rejected
without a compiler fallback or a Lake call.

The expanded native runs took roughly 774 MiB peak RSS per process. These are
small CPU diagnostics, not representative corpus throughput or a speedup claim.
The fresh two-clause census measured direct compilation at 0.08495 s/span and
its one learned inference at 0.12165 s/span. Different input sets and cold-start
costs make these unsuitable for direct comparison with the earlier campaign.

For these timings: `bridge_names=[]`, `legal_ir_target_count=0`, provers off,
metric disk cache off/not invoked, one legal worker, no sample memory,
temperature 0. **No bridge-on evaluation timing was measured.** Checkpoints and
schema projects were fresh; this does not claim the entire OS/process cache was
cold. No weights were downloaded, and no context window was increased.

Fresh-process native resumes rejected changed learning rates before creating
output; existing output overwrite was rejected; zero-deadline runs created no
candidate; parent files remained unchanged. A deliberately corrupted artifact
in a fresh, independently bound registry was rejected before training with
`artifact bytes or digest mismatch`. The first corruption harness expected the
wrong error wording; its original failure is retained alongside a corrected
fresh-process verification. An earlier copied-registry attempt only tested the
durable directory binding and is not counted as checksum evidence.

## Census and remaining integration work

The local paired bundle preserved exact producer outputs and three deferred
goals, including an unavailable-capability case. The exchange bundle preserved
one repair packet and one training goal, whose `observation_evidence` matches
the immutable census. The second clause did not invoke the learned model;
its unavailable status is not a conversion success.

The test also exposed boundaries that must be completed before claiming a
production distributed decoder pipeline:

1. Add explicit learned-formula fields/adapters to production census export.
   Census-v3 currently retains the complete prediction in `input_json`; paired-v1
   needs the explicit adapter used by this test harness.
2. Define comparison rules for compiler metadata. Current exact AST comparison
   includes temporal metadata and can report representational disagreements.
   Keep the complete raw outputs and distinguish these from lost semantics.
3. Wire the new formula runtimes into the fleet worker and Hub exchange codecs,
   then test real multi-machine sparse updates and Hub readback. Quack loopback
   control success does not cover those adapters.
4. Improve legal compositional generalization without fitting this held-out
   case, and establish independent held-out native/source-to-logic coverage and
   family-backend validation. Structural Lake success must not replace either.

No Hugging Face upload, supervisor task execution, archived-checkpoint rewrite,
or live census-service restart was performed in this test campaign.
