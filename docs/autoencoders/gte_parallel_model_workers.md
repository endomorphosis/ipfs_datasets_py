# CPU inference workers for parallel 8D and 384D paths

The [parallel launcher](parallel_lineage_execution.md) has an inference worker for existing 8D and 384D backends. It checks exact local checkpoint and input files, binds their identities to the selected lane, applies CPU limits before importing models, and writes separate reports. The 768D slot remains explicitly unavailable until its producer and decoder exist.

Use [run_gte_model_worker.py](../../scripts/ops/autoencoder/run_gte_model_worker.py) through the launcher. [gte_worker_contract.py](../../ipfs_datasets_py/logic/formalization/autoencoder/gte_worker_contract.py) supplies strict JSON/pin checks, process budgets, state leases, and exclusive output writes. These workers perform inference; the [transfer plan](gte_multilingual_migration_plan.md) still governs teacher qualification, training, and distillation.

## Supported selections and inputs

| Runtime identity | Checkpoint pin | Inference row fields |
| --- | --- | --- |
| `legal_ir:legacy_v1` | Exact historical numerical checkpoint JSON | `id`, `source_text`, `embedding` with eight finite coordinates and explicitly declared producer |
| `legal_ir:legacy_linguistic_historical_blank_en` | Exact `manifest.json` from a saved linguistic bundle; loader also checks `core.state.json` | `id`, `source_text`; vectors are regenerated by the bound linguistic feature codec |
| `DOMAIN:source_training_v2` | Exact shared source sequence checkpoint for Legal, Intent, Security, or UI/UX | `id`, `source_text`, `embedding` with 384 finite coordinates |

The linguistic identity is a module profile, not a new registry registration. Its feature hashes are distinct from pretrained semantic embeddings and from historical 8D inputs whose original producer is unknown. The worker checks the generated linguistic producer identity against the actual loaded model. Supplied external vectors remain declarations; file hashes and dimensions cannot authenticate their encoder outputs.

Input JSON has exactly `schema: "gte-parallel-inference-inputs/v1"`, `domain_id`, `representation_id`, and `rows`. Row fields are closed. Authored targets, teacher outputs, grouping metadata, and sidecars are rejected before model inference. Keep reference comparisons and dataset provenance outside that neural-input file.

The historical 8D numerical decoder uses a reconstruction safety projection that can return the input target vector exactly. Its report discloses `reconstruction_target_access: true`, `reference_ir_target_access: false`, and `reconstruction_is_fidelity_evidence: false`. Reconstruction success does not qualify a learned formula decoder. The 384D path generates candidates without target prefixes; invalid candidates remain in the report.

## Pinned worker configuration

Each worker configuration has exactly these fields:

```json
{
  "schema": "gte-parallel-model-worker/v1",
  "lane_id": "source_384d",
  "dimension": 384,
  "runtime_id": "legal_ir:source_training_v2",
  "representation_id": "your exact declared producer and transform profile",
  "domain_id": "legal_ir",
  "mode": "infer",
  "checkpoint": {"path": "checkpoint.json", "sha256": "full SHA256"},
  "dataset": {"path": "source-only-inputs.json", "sha256": "full SHA256"},
  "resources": {
    "device": "cpu",
    "threads": 1,
    "max_rows": 3,
    "memory_limit_mib": 16384,
    "cpu_time_limit_seconds": 120
  }
}
```

This illustrates the schema; use actual profiles and complete hashes. Reference paths resolve against the worker configuration's parent. The worker command receives `--config` and `--expected-config-sha256`; the coordinator supplies the lane/runtime/representation/checkpoint and private state/output environment bindings. A mismatch fails before numerical inference.

Thread and offline flags are set before model imports. CUDA devices are hidden. POSIX limits cap process virtual address space and total process CPU time; existing tighter limits remain in force. Each worker also restricts CPU affinity. These are local process budgets, not aggregate memory reservation. The launcher timeout bounds wall time separately. Recorded peak RSS and CPU usage describe the actual process, including startup.

Caches live under the worker's private state directory, and the Legal metric disk cache is disabled. A cooperative exclusive `worker.lock` permits one owner of that state. Existing or stale locks are never reclaimed automatically. Workers recheck input/configuration/checkpoint and implementation hashes before writing an exclusive `inference-report.json`. Neither training nor checkpoint publication occurs through this inference entry point.

An optional `--start-gate PATH` allows an owner to wait for both workers' `model_ready` log signals and write a fresh closed JSON gate:

```json
{"schema": "gte-parallel-inference-start/v1", "start_monotonic_ns": 123456789}
```

Supply a genuinely future monotonic timestamp within 60 seconds on the same host. The gate is read-only to workers; they retain its exact hash. Waiting for the gate is bounded. This diagnostic start control shares no model or optimizer state. Ordinary inference can omit it and run immediately after each model loads.

The first attempt reserved a fixed start before model loading; startup exceeded it and both workers failed explicitly. That [failed report](../../../../artifacts/gte-parallel-model-smoke-20261001/run-01/dispatch-report.json) is retained. Run 02 used readiness signals before releasing the gate. Each fresh process took roughly two minutes end to end under these local settings; this startup observation is separate from the timed inference interval.
