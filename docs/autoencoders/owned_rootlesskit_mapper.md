# Finite owned RootlessKit mapper qualification

This is the qualification protocol for one known-source RootlessKit UID/GID
mapping fixture. Its normal and controlled cancellation observations are
separate from Docker execution, private container PID namespaces, model work,
training convergence and formalization of any law. Only a successful
`lake build <Lib>` can supply a Lean admit. This fixture does not run Lake.

The owner, launcher, mapping fixture and verifier remain reviewed artifacts,
not a portable production launcher. A successful report supports only the
exact source generation, host boot, original process births, runtime inode,
native grants, cgroup controls and finite modes it records. Public JSON
receipts and source/request/nonce labels are observations, not capabilities.

## Startup and productive work

The administrative F07 bootstrap binds one new paused user service by
MainPID, birth, invocation, cgroup inode and effective controls. It does not
lend its native lease to that service. The owner creates its private controller
leaves and binds original cgroup descriptors. It forks the guardian while
exactly one Python and Linux task exists, before native heartbeat threads.
The outer source read lease and original kernel descriptors survive the fork.

After obtaining its own real base grant, the owner sends the original root
token only over a private pipe. The guardian acquires a real full-envelope
native child in the actual root lane and constructs `KernelDrainFence` over
the original worker. The secret never enters argv, environment, files or
reports. The mapper receives neither root nor guardian scheduler authority.

The bootstrap is an actual direct new-session child. The unchanged owner API
attaches and accounts it while paused. The owner then moves that original
birth into the original worker cgroup. Immediately before releasing `G`, it
checks source/native bindings, guardian liveness and exact actual child/root
rows, membership, full envelopes and hierarchical usage. These checks also
surround productive observations.

The pinned fixture execs RootlessKit with no network or port driver and no
private PID namespace. Its `/etc` and `/run` copy-ups use namespace-private
tmpfs charged to actual native RAM. It starts no daemon, imports no image and
downloads no weights.

## Drain, cancellation and retained claims

Normal stop, pipe EOF, native cancellation, owner absence, deadline or source
failure routes to cleanup through the original held worker. Cleanup does not
require a successful productive observation. The guardian drains, the parent
reaps original births, and the guardian verifies the original bounded runtime
and immutable charge. It fsyncs pre-release evidence while its real child
remains charged. The fence repeats exact drain before child release.

The parent requires the guardian's terminal acknowledgement and reaping,
original worker emptiness, original birth disappearance, and independently
verified absence of that actual native child and other root consumers before
any base finalization or context exit. The shared host PID namespace is never
required or claimed to be empty.

In `controlled_cancel`, a freshly verified live mapper is cancelled through
the actual owned `ResourceLease.cancel()` API. Productive work stops; cleanup
continues without treating revocation as release authority. After positive
drain and reaping, the failed disk claim remains retained in full with its
unchanged 128 MiB external charge. This mode produces no successful seal or
base finalization.

In `normal`, the explicit base finalization follows stopped checks and durable
regular evidence. Runtime regular files/directories are fsynced without
following aliases. Runtime sockets and supported internal aliases are not
relabeled as ordinary strict files. The immutable charge is never lowered.

Unknown cleanup holds original descriptors, source lease and actual surviving
native custody. The finite outer service fallback is an unqualified failure;
simultaneous guardian death and hostile migration are not qualified.
