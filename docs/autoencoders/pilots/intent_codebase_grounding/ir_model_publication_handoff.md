# Retained IR model publication and ModelManager registration

The finite audited inventory contains **665 distinct retained checkpoint blobs**,
published across **17 public Hugging Face repositories** and registered through
the genuine ipfs_accelerate_py ModelManager API in the selected persistent store. The
initial named batch added 24 records; the expanded campaign batch added 641, with
fresh native per-record queries, separate cold native readback and a genuine
manager reload confirming 665 persisted records and catalog associations.

The initial 24 release was a named inventory batch, not an exhaustive census. Its
exact handoff bytes and original receipts are retained in historical snapshots.
The supplement adds original campaign weights, diagnostic/ablation variants,
source-text reconstruction heads and auxiliary components. 665 serialized blobs
does not mean 665 independent trained parameter sets. No weights, embeddings,
training, numerical inference or distillation were generated by this phase.

## Selected persistent store and historical database transition

The target is external/ipfs_accelerate/model_manager.duckdb. The initial authorized
transition was 0 -> 24; the supplemental authorized transition was 24 -> 665. Each
new record was checked with a fresh parameterized native table query independent
of manager.models. Open native connections may share the same database cache.
Original handles then closed; separate cold native readback, genuine manager
reload and canonical catalog checks establish the recorded persistence outcome.
The final cold catalog revision and exact database pin are in the JSON handoff.

The driver explicitly selected the existing absolute Accelerate store.
ModelManager otherwise defaults to MODEL_MANAGER_DB_PATH when set, or to
./model_manager.duckdb relative to the caller's working directory. The selected
path matches the default only when run from the Accelerate package directory;
this phase does not verify alternate stores or a running supervisor's configuration.

The supplemental driver completed all 641 imports and its cold checks, then
failed while creating the final database receipt because its 512 MiB hashing
bound was exceeded. That failure is preserved. A separate read-only completion
authenticated the original results and verified the unchanged actual target;
fresh genuine catalog corroboration used an isolated copy. No registration
calls were retried. The copy's input pin is historical because manager
initialization may change that copy; it is separate from the active catalog.

Exact before-import database snapshots are retained. The old sealed live DB pin
and intermediate 24-record DB are historical after these explicitly authorized
writes; this phase does not claim those old live endpoints remain unchanged.
Original checkpoint, inventory and vector assets are separate preservation
scopes. Prior stable catalog metadata was preserved; same-ID foreign conflicts
are refused rather than overwritten.

Serving configuration remains absent, and runtime-ready, teacher-qualified and
proof-authority flags remain false for every record. Optional constructor Python
imports and local fallback cache/graph initialization were allowed; model loading,
training, deployment and remote IPFS behavior were not activated. Another running
supervisor's cached manager and alternate configured store were not refreshed.

## Validation and next gates

151 source controls passed 453 setup/call/teardown phases: 60 publisher controls and
91 importer controls, including component isolation. These use inert APIs and
factories. Actual Hugging Face publication, anonymous verification and native
database persistence have separate completed receipts.

The next work keeps 8D, 384D and 768D paths parallel and reuses the exact retained
assets, original embeddings, codec/source contracts and teacher candidates:

1. Connect each physical lane's DuckDB/DuckLake rows to exact format/profile/
   checkpoint/source/span/corpus/proof identities; refresh a running supervisor
   only after verifying its configured store.
2. Add native Codebase contracts separately from borrowed Security payloads and
   compiler-feature autoencoders. Register supported Legal canonical, source-text,
   scope/boundary and reconstruction formats separately.
3. Measure legal text -> LegalIR -> reconstructed original legal text. Exact full
   canonical IR, exact original UTF8 text and normalized-text scores are separate;
   all attempted rows stay in denominators. Parser assistance, deterministic
   rendering and retained-source restoration remain explicit.
4. Evaluate existing 8D/384D checkpoints on their original retained corpora and
   separately on native-v3 caches. Vocabulary mismatch is not a training-failure
   claim against another corpus. Free-generation correctness and source fidelity
   must support any teacher decision; low teacher-forced loss alone is insufficient.
5. Reuse retained parameters for native 768D decoder initialization and alignment.
   Admit authentic same-source multilingual-GTE 768 vectors and explicit geometry/
   codec mappings; do not pad 384D vectors or regenerate old embeddings as a
   substitute. The 512/8192 encoder ceilings are declared limits, not qualified
   decoder spans or reconstruction capability.
6. Begin distillation only after held-out coverage, IR/text reconstruction, span
   and free-generation gates qualify the selected teacher and intended output
   format. Keep ablation runs/checkpoints distinct within each lane.
7. Ground Intent planning in the current repository revision and proof-cache/
   verifier evidence before supervisor actions. Formalized candidates remain
   separate from verified proofs.
