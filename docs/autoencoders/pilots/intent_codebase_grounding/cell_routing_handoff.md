# Typed IR cell routing and remaining improvement plan

The standalone resolver authenticates the original twelve-cell plan and exact declared checkpoint/cache references. It does not initialize decoders, modify prior models, recompute embeddings, create stores, or widen the existing runtime defaults. The four IR families retain separate 8D/384D/768D cells. This local draft is based on commit 88da35ffde25cd872d86d43a2a9b44b3ef58e981; GitHub integration remains a separate gate.

## Qualified behavior and evidence

The new `resolve_ir_cell_route` takes a closed directory pin, a list or tuple of twelve closed inventory pins, and exactly `ir_family_id`, `dimension`, `dimension_role`, `task_id`, `checkpoint_sha256`. Pins contain absolute `path`, positive bounded `bytes`, and lowercase `sha256`. Null selects no decoder. 786D, booleans, unsupported tasks/roles/families, ambiguous digests, cross-cell checkpoint selections and aliased planned storage/Hub destinations reject. Existing mismatched, nonregular or drifting files reject; absent declared references remain unavailable with their original pins. It hashes selected checkpoints and selected-cell cached files without deserialization or matching-by-hash repair.

All thirteen manifest bytes authenticate, including unselected cells. Archived copies may be passed explicitly: logical directory locators and cell identity are validated, but this does not establish currentness over the original physical manifest locations. Each reference retains its exact declared inner path; stable Hugging Face snapshot aliases are allowed with alias/target/descriptor witnesses. Reads are bounded and checked per file, not an atomic cross-file snapshot or universal ancestor containment.

The corrected selected run passed 139 cases across 46 functions, with 417 successful setup/call/teardown phases, no exclusions, failures or skips. Its private fixtures use synthetic bytes, not runnable models. The original-inventory run made 25 explicit requests: 12 unselected routes and 13 saved-checkpoint selections. The thirteen selected checkpoint records, twelve distinct cached split files and one shared descriptor source authenticated at their exact declared paths. The earlier startup run collected no tests: pytest's default writable `/dev/null` log was refused. Its harness and evidence remain unchanged; v2 redirects only that log to its private run.

## Reuse and qualify the existing decoders

1. Acquire the exact package initializers and consumer/runtime generations before integration. Add an explicit adapter for this resolver; reject incompatible family/role/task/checkpoint/profile requests before loading or inference. Keep metadata declaration matching separate from a runtime admission record. Bind codec/schema, encoder and tokenizer revisions, pooling/normalization, source-access mode, input and latent width, decoder architecture, task, split/vector receipts, store incarnation and immutable serving head. A historical model association does not imply a current serving head.
2. Reuse the original source/target pairs, splits, cached embeddings and learned checkpoints with their pins. 8D is not uniformly an input embedding: CodebaseIR latent8 uses 53 inputs, SecurityIR latent8 uses 52, and IntentIR latent8 uses 12. LegalIR's 8D donor has unknown historical encoder/tokenizer provenance. Distill their demonstrated task knowledge only; do not fabricate a GTE 8D encoder or treat structural features as source embeddings. The 384D envelopes owned by CodebaseIR retain unchanged SecurityIR numerical payload; qualify a native CodebaseIR task independently rather than relabeling it.
3. Audit training, parser and evaluation exposure before qualifying 384D donors. Reuse preserved split groups for development/replay according to their actual exposure; retain split identities and obtain an independently sealed, source-disjoint evaluation set for teacher qualification. The saved LegalIR metric records describe exposed validation and archived exposed examples, so those prior scores are not independent held-out teacher evidence. Separate source-free decoding, compiler-conditioned decoding, parser assistance and source restoration. Inspect actual saved checkpoint geometry, codec/vocabulary and producer identity in a separately bounded model cohort. Measure quality and coverage alongside loss. No checkpoint becomes a teacher solely because bytes match, a task appears in an inventory list, or training loss falls.
4. Retain the authenticated LegalIR 768D inherited initialization. Verify donor contributions, mapped shared decoder weights and any newly initialized adapter parameters. For each family, use its own codec and decoder head; transfers across families require explicit semantic alignment. Compare inherited-only,384D-only,8D-only,dual-donor and fresh-initialization controls on the same held-out task. Teacher outputs/hidden states/IR logits must be tied to the same authentic source spans; preserve loss terms and original split identities.
5. Native 768D inputs remain unqualified. Reuse 384D cached vectors for 384D teachers and pair alignment;768D source conditioning requires authentic pinned 768D producer vectors on the same source records. Do not silently regenerate, pad or relabel 384D vectors. Any newly generated 768D embeddings need a separately admitted, immutable derivative corpus with source/split/provenance receipts. Freeze encoders initially, fit a small 768D adapter against eligible learned decoder weights, then unfreeze gradually only after held-out gains. No training or embedding generation was performed here.
6. Increase spans in measured stages. The original profiles declare 512 and 8192 encoder ceilings; all qualified source-span limits remain unknown. Test actual tokenization, truncation, overflow, clause boundaries, cross-span relations, hierarchical aggregation, source byte spans, multilingual accuracy and memory/latency before increasing budgets. The Alibaba model card specifies768 dimensions and8192 tokens; this is an encoder ceiling, not a qualified decoder reconstruction guarantee. [GTE-small model card](https://huggingface.co/thenlper/gte-small), [multilingual GTE model card](https://huggingface.co/Alibaba-NLP/gte-multilingual-base).

## Legal text round trip

Use `original UTF-8 legal text -> LegalIR -> generated legal text` with pinned source and target records. Report exact byte equality first, then separately normalized-surface equality, character/token edit distance, clause/IR reconstruction and formal/semantic consistency. Preserve punctuation, whitespace, names, references, numbers, ordering and Unicode in the exact-byte target. Report each metric's denominator, decoding budget, coverage, failed parses and truncation; never count skipped examples as exact reconstructions.

Evaluate two separate products: source-free learned generation and archival restoration using an explicit retained surface/residual channel. A lossy pooled embedding or semantic IR need not retain the information needed to reproduce every original spelling and formatting choice. If exact archival recovery is required, design and pin that surface channel separately and attribute its contribution. Parser-assisted recompilation, compiler features, target copying, source fragments and residual lookup cannot be credited as source-free decoder reconstruction. Decoder evaluation must identify which inputs were accessible. Held-out source-free quality, not archival copying, gates teacher qualification and distillation.

## Independent stores, proof index and IntentIR planning

Create twelve physical stores only in a later admitted operation, each with concrete registry/index DuckDB, DuckLake catalog/data, immutable artifact root, writer lock, restore incarnation, capacity and Hugging Face model/dataset destinations. The current templates enforce cell separation but no database or remote repository exists by virtue of a template. Qualify cross-cell rejection, concurrent writers, bounded ingestion, schema migration, crash/reopen and independently restored-store identity. Pin model/vector/corpus associations; any cross-cell transfer is an explicit edge with lineage, never an implicit path fallback.

For each repository scan, bind committed/root source identity, file/span byte CIDs, inventory generation and currentness receipt to canonical CodebaseIR nodes independently of model width. Preserve opaque/unparsed spans. Bind family-specific encoder/decoder/profile/projection receipts to structural and formal candidates. Separate source observations, compiler facts, model hypotheses, checked obligations and solver results. Proof-cache keys must include canonical obligation, logic family/domain, assumptions, dependency CIDs, producer/solver versions and applicability/currentness receipts. Generated formal text remains a candidate until its correspondence and proof are checked.

IntentIR stays a separate typed IR. Ground desired effects/preconditions in exact current CodebaseIR symbols, calls, spans and obligations. The `ipfs_accelerate_py` supervisor receives typed candidate actions with provenance, proof status, uncertainty and resource limits. Reobserve effect-time dependencies before accepting a plan/action. On-the-fly CodebaseIR training produces a candidate checkpoint from a frozen scan/split/corpus; training and publication use separate budgets and no automatic serving-head promotion. SecurityIR checks security obligations and LegalIR checks legal clauses through explicit projections; they do not share an untyped latent or proof authority.

## Separate remaining infrastructure cohorts

Native Git configuration is still cooperatively fenced rather than consumed immutably. The audited next slice is an opt-in operation-owned configuration/metadata capsule preserving ordered duplicate/bare values, scopes and include resolution, with explicit committed HEAD/index/ref/object roots. Environment flattening alone is insufficient because local configuration remains readable and scope semantics can change. Reject external commondir/linked-worktree/alternate-object profiles until admitted. Immutable consumption or isolated execution and actual native path containment need new qualification; descriptor/root witnesses alone cannot establish them.

The guarded restart slice first covers the two historical catalog/policy replay cases in a fresh pinned `-I -S -B` child. Close parent connections, repeat source/native admission, reopen the exact private writable DuckDB/CAS and reapply connection settings and finite child limits. The live current-head case additionally requires bounded cold Git admission. Independently executed replay does not establish power-loss durability. Real submodules, opaque/noncommitted currentness, positive code/formal/domain/applicability correspondence and full runtime dependencies remain separate pending gates.

Finally compare reviewed local commits and exact retained weights with fresh `origin/main`, resolve overlap in an isolated checkout, validate the combined package/consumer scope and then integrate the reviewed payload. Keep commit/bundle receipts and explicit source/model/corpus provenance. This phase makes no fetch, merge or push and does not claim the local metadata draft or previous model weights are already in production.
