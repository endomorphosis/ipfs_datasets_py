## What the combined subject binds

The [combined-review API](corpus_definition_use_review_v2.md) replays the
[existing alias candidate](corpus_definition_use_v2.md), both complete original
source/candidate input groups, context packets and registry/query/lookup inputs.
Its subject binds the full joint AST:

```text
donor_definition ∧ (consumer_definition ∧ explicit_alias_assumption)
```

The alias remains an unproved unary biconditional assumption. Original endpoint
reviews cannot approve the new joint interpretation. The distinct combined
scope, claim/action/audience and review contract bind both originals, the exact
graph and joint AST, all declared contexts and the required dependency closure.
Authentication delegates to the existing signature engine under supplied keys
and policy; it supplies no actual reviewer, trusted registry or legal truth.

Lookup still has
`lookup_coverage=representative_first_occurrence_whole_predicate_assumption` and
`per_occurrence_lookup_verified=false`. Repeated consumer roles remain explicit,
but one representative lookup does not establish governing scope for each use.

The [new joined regressions](../../tests/unit/logic/autoformal/test_definition_use_review_v2_graph_exchange.py)
exercise public Parquet export and a fresh-process graph reader. They require
the exact combined graph, full joint subject hash, closed `USES_DEFINITION`
endpoints and original evidence CIDs, with all twelve original endpoint byte
inputs retained separately. The graph loader supplies graph custody; it does
not reconstruct the external source or review companions.

Both family cases use two real generated fixture signatures, one for each
review role, with blank context evidence. They require authentication count two
while context prerequisites remain blocked, accepted-view eligibility stays
false and every authority flag stays false. These are cryptographic fixture
controls, not actual legal/formal reviews or verified human identities.

The third regression rebuilds the actual searched donor table with a competing
definition. It updates current observations with the rebuilt partition's real
digest and table pin. The required closure and combined graph must become stale
with a propagation witness; both original graphs remain reusable under their
declared dependencies. Existing signatures remain authenticated, but review
prerequisites fail. Fresh resolution must report ambiguity and refuse a new
combined candidate. No invented zero-hash observation supplies this control.

explicit caller-declared V2 interpretation to exact sampler units, roles,
physical intervals and required parent contexts. It retains the complete
population and ordered response commitments. It authenticates no review and
cannot infer that a source declaration agrees with the caller's AST.

The [executed C driver](evidence/legal-ir-definition-use-review-v2-integration-20261015/run_actual_definition_binding.py)

infer person/grade sorts, membership relations or governing applicability.

560 subjects, 8,400 unanswered question slots and 3,360 original open context
obligations. Each family selected the exact scope/contributor subjects while
all 560 remained pending and actual responses and reviews remained zero. Each
definition-only graph has 15 nodes and 26 edges. Outputs are bounded JSON
candidates, bindings, populations and provenance; C performed no Parquet
exchange, definition-use composition or native Lean execution. Its replay
receipt SHA256 is
`3e2b421aed87627b540712de89d7d8cfc00b7fd1dcb9966ac54044d62383c82b`.
