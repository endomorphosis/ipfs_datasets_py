# Definition review with declared primary evidence

`legal_source_sampling_primary_review_v2` prepares a fresh unsigned V2 definition-review subject whose dependency closure includes the sampled-source/primary association and every exact primary witness. It replays the existing association validator and uses the public dependency and V2 definition-review builders. The old candidate, correspondence, preparation, subject, manifest and signatures remain unchanged.

This supplies a reviewable evidence closure. The existing signing domain covers the declared graph/AST interpretation and context; it has no explicit official-source/primary-package equivalence decision. Source equivalence, governing version/applicability, independent legal and formal interpretation, and authenticated exposure remain unresolved. No assessment or signature is created, every authority flag remains false, and training/evaluation-gold masks remain integer zero.

## Exact inputs and output

Call `prepare_primary_association_definition_review_v2(association, correspondence, binding_result, previous_subject, primary_index, *, expected_association_sha256, association_replay_inputs)`. The replay object contains exactly the five keyword arguments accepted by the original association preparer: `expected_correspondence_sha256`, `correspondence_replay_inputs`, `mapping_raw`, `expected_mapping_file_sha256`, and `expected_index_sha256`. Original byte transports, omitted-versus-provided sampler keywords, whole-record pins and live index custody retain their existing contracts.

The envelope contains a small sealed `preparation` record plus separate plain `subject` and `dependency_manifest` companions. `primary_association_definition_review_sha256` commits the complete envelope. Despite its name, validation's `expected_preparation_sha256` is this whole-envelope hash, not just the sealed preparation record's hash. Independent expected pins are caller commitments; self-hashing does not authenticate them.

The preparation commits full canonical references to the unchanged association, correspondence, old subject/preparation and old manifest; it also binds the new subject and manifest, original population reference/counts, selected roles, ordered context slots, every primary artifact reference and observed producer sources. The complete old population (560 subjects in the retained §101 component) remains bound through the unchanged association; it is not copied into this new envelope. Full canonical manifest hashes and existing internal `manifest_sha256` remain distinct. `primary_index_ref` likewise distinguishes the internal `index_sha256` from `full_canonical_sha256`.

A valid unresolved association returns `blocked_unresolved_primary_association`, retains its issues and has null new companions. A healthy declaration prepares an unsigned subject; it does not close any legal context obligation.

## Preserve the old dependency population

Every original manifest artifact, pin and edge remains in its original order, including unrelated artifacts, null pins and missing targets. New artifacts bind the complete association, unchanged correspondence, unchanged old subject and unchanged old manifest; all original primary record references and the canonical mapping reference are added unchanged. Producer-source artifacts also bind the preparation implementation. The original graph root depends on the association, which depends on the added evidence.

The adapter derives the new ordered forward closure and supplies it to the existing public subject builder. Collisions with any old artifact ID or any old dependency target refuse, including equal-hash collisions. An added primary artifact cannot silently satisfy a previously missing target. No endpoint is renamed, no old occurrence is deduplicated, and no new semantic graph is created.

The new subject keeps the existing V2 schema/action/audience and unchanged native preparation, but its larger dependency closure changes its full identity. Old claims retain their original scope and cannot authenticate the new subject. Future authentication must first replay this envelope, then use the public `assess_definition_reviews_v2` API with the new subject/manifest, independent pins, registered keys, policy, exact reviews and current evidence observations. That existing API does not express an explicit source-equivalence verdict or confer legal truth, training eligibility or Lean admission. Collect blind interpretation targets before exposing these candidate-bearing artifacts, and record later exposure through the existing review owners. Primary source-package fields remain producer declarations: historical acquisition, transformation and version correspondence need independently supplied original evidence.

## Bounds and execution

Public import loads only the standard library. Preparation detaches finite ordinary inputs before loading operation owners. Inputs are capped at 128 MiB; the original association/correspondence/subject and raw mapping keep their existing bounds. Dependency construction retains the existing 4,096-artifact and 16,384-edge ceilings. The whole envelope is capped at 4 MiB with depth/node bounds; its sealed preparation still obeys the common one-MiB, depth-20 and 25,000-node limits. Complete overflow refuses; no population or evidence is truncated.

The caller's existing native owner supplies resource admission, process supervision, storage, durability and release. This adapter starts no owner, download, model, reviewer or Lean process.
