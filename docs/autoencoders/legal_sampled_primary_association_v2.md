# Sampled source declarations and original primary anchors

The additive `legal_source_sampling_primary_association_v2` owner records an unsigned caller mapping between an unchanged sampled V2 source/review correspondence and a live original-primary section index. It replays the existing correspondence validator, performs one literal section lookup, and reuses `legal_source_graph_proposals.required_primary_artifacts` for selected original witnesses. It does not change the candidate graph, review subject, dependency manifest or primary index.

This closes a mechanical association interface. Matching identifiers cannot establish equality of an official HTML document and a primary package, legal applicability, agreement with a declared AST, authenticated review, training eligibility or Lean admission. Those remain separate evidence obligations.

## Inputs and replay

Use `prepare_sampled_primary_association_v2(correspondence, binding_result, review_subject, primary_index, ...)`. Supply the independently retained full sealed-correspondence canonical SHA256 and the existing index receipt’s internal `index_sha256`, the exact original keyword arguments accepted by `validate_definition_review_correspondence_v2`, original mapping bytes, and their separately supplied SHA256. Validation takes the resulting sidecar and an additional full sealed-record hash, then repeats the entire preparation. A self-computed hash provides no independent trust.

The closed mapping has seven fields:

```json
{
  "schema": "legal-source-sampling-primary-association-mapping/v1",
  "correspondence_sha256": "<complete sealed correspondence hash>",
  "source_identity_sha256": "<full canonical source identity hash>",
  "source_occurrence_cids": ["<every physical occurrence CID, in original order>"],
  "legal_id": "usc:us:10:101",
  "section_entry_cid": null,
  "source_package_entry_cid": null
}
```

Replace nullable anchors with explicitly declared primary IDs when available. Nulls and valid unmatched anchors produce named unresolved dispositions. Invalid source, occurrence-order, correspondence or index commitments refuse. Literal legal IDs are passed unchanged to the existing release-shape validator and index; aliases and leading zeros do not resolve through normalization. The sampled source's document/version identity and the primary repository's Git revision remain separate.

The index must be the exact live `PrimarySectionIndex`, built from independently pinned original reconstruction candidate JSONL and report. Export lineage and canonical Parquet cannot substitute. Guard the index for its entire context-manager lifetime. Selected artifact hashes address original `record_json` UTF8 bytes, distinct from wrapper/row hashes and canonical export hashes. The index’s internal `index_sha256` is also distinct from a hash of the complete receipt file or its full canonical JSON.

## Retained evidence and limits

The sidecar retains the complete old subject population and counts, ordered roles and occurrence/context links, source/candidate/subject/dependency references, full primary-index receipt and identity, every literal lookup observation, raw mapping transport and hash, selected original artifact witnesses, and producer-source pins. Duplicate, conflicting, quarantined, missing and other-kind primary observations stay visible in the complete lookup. Healthy declared anchors still have declaration-only status. Every authority flag is false and both training and evaluation-gold masks are zero.

Public import uses only the standard library. Preparation bounds and detaches ordinary JSON/raw-byte inputs before loading operation owners; duplicate JSON keys, unknown mapping fields, nonfinite numbers and nonordinary containers refuse. Mapping bytes are capped at 64 KiB, input detachment at 128 MiB, physical occurrence declarations at 256, and complete lookup at 16 MiB. The common sealed record's stricter one-MiB/depth/node limits still apply to the whole result: overflow refuses instead of truncating populations or witnesses.

The caller's existing native validation owner supplies runtime, storage, process and durability custody. This owner creates no lease, model, reviewer signature, source download or theorem process.
