# Source-corpus extension of the LegalIR plan

This metadata-only planning increment updates the existing
[corpus roadmap](../../legal_ir_uscode_corpus_improvement_plan_20261015.md) and
[execution design](../../legal_ir_span_graph_lean_execution_plan_20261016.md).
It explicitly connects `justicedao/ipfs_uscode` to the span cache, scoped
term/entity/definition/norm graphs and a coherent Lean 4 corpus. The reviewed
repository baseline is `ff8a01fd04c741f892572e7f28cba777d4dfd472`.

The plan preserves existing task dependencies, trained assets, the separate
8D/384D/768D paths, family/schema/task checkpoint identities, native resource
owners, source/review interfaces and graph/Lean builders. It creates no new
scheduler, review authority, AST, database or model release.

The source manifest declares 62,931 corpus rows and 62,931 384D vectors. These
are not newly counted physical laws or authenticated numerical inputs. Its
852,161-byte manifest matches the prior qualified 74-file primary graph
selection; retain that selection's original provenance and receipts. This is
not a complete-release equivalence claim or another payload replay.

The first new data job is the existing-owner corpus inventory and reversible
source/span correspondence, after exact selection and resource admission.
Model engineering can proceed under an explicit supervision policy in parallel
with review of one definition, one complete norm and a second physical use.
Accepted statutory graph/Lean work requires reviewed supported meaning; it does
not wait for completion of a newly trained action head.

Full API bodies and selected control-plane preimages remain private local
research artifacts; immutable primary URLs and their hashes are retained in
the public metadata summaries. This is not a self-contained corpus replay bundle.
No Parquet, checkpoint, embedding or generated-output payload was downloaded;
no product imports, tests, database operations, inference, training, human review,
data/model upload or Lean build ran for this planning update. Historical native
qualifications remain attributed to their original evidence, not counted as new
work in this phase. Documentation publication is separate from future data/model
or corpus publication.
