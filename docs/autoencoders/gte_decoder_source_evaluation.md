# Source-only comparison of inherited logic decoders

The comparison runner evaluates the original learned 384D and 8D heads using
their existing cached inputs. When native multilingual receipts and saved
generations become available, it evaluates the original 768D initialization,
the affine-aligned initialization and the aligned-start trained interfaces on
the same source identities. All three independent execution lanes continue
under the [parallel lane contract](parallel_lineage_execution.md).

This work reuses the original assets and embeddings. It neither regenerates
old vectors nor manufactures native 768D inputs from old coordinates. Decoder
generation uses only a source vector and tokens already generated by that
decoder. A separate scorer reads the original reference after generation.

## Cohorts and evidence limits

| Head | Preserved source inputs | Evaluation role | Qualification limit |
| --- | --- | --- | --- |
| Primary 384D typed JSON | All 60 original V2 validation vectors | Exposed validation regression | This split was already used for selection; it is not an independent holdout |
| Auxiliary 8D grammar | Both original authored synthetic training latents | Training diagnostic | Two training examples do not establish generalization or source fidelity |
| Each 768D generation | Exact cached multilingual receipts for those same 62 sources | Matched regression or diagnostic comparison | Native producer authentication and independent fidelity remain separate gates |

The 8D inputs are the original raw training latents reconstructed under the
saved latent contract, with their parser-feature provenance retained. They are
not arbitrary linguistic feature vectors or truncated GTE embeddings. Each
head retains its original vocabulary, canonical grammar and source identity.

The [evaluation plan contract](../../ipfs_datasets_py/logic/formalization/autoencoder/gte_decoder_source_evaluation.py)
first admits the complete original 242-source audit. It selects evaluation rows
from the original archives and looks for each source in the complete admitted
native receipt cache. It never uses the selected training batch as a substitute
for validation coverage. A cache sufficient for the 16 primary and two auxiliary
training rows can leave all 60 primary validation sources missing. Conversely,
a compatible validation receipt can be evaluated even while training inputs
are unavailable.

Missing and quarantined native sources remain in every variant's row inventory.
Reports give selected, evaluated, missing, quarantined and unavailable-model
counts separately. Exact-match rates include every generated failure in the
evaluated denominator; selected-cohort rates additionally count unevaluated
rows as unsuccessful coverage. A partial comparison cannot qualify a full
cohort or infer a student's accuracy on missing inputs.

## Generation and scoring

The [numerical generation helper](../../ipfs_datasets_py/logic/formalization/autoencoder/gte_decoder_source_generation.py)
accepts a private model, an input vector, a head and fixed inherited decoding
controls. Its API receives no source text, reference, reference prefix or target
length. Greedy generation starts with BOS and stops at raw EOS or the inherited
budget. The original 512-token primary and 64-token auxiliary budgets include
BOS, allowing at most 511 and 63 new tokens respectively. These decoder output
limits remain independent of the planned 8192-token encoder input limit.

PAD or extra BOS predictions remain visible and count as invalid syntax; no
grammar mask, reference-built candidate list or target-length stop rule hides
them. Early EOS, malformed targets and token-limit runs count as unsuccessful
reconstructions. Strict scoring checks canonical typed IR, exact target match,
field matches and token edit distance after generation. Syntax validity alone
does not establish exact reconstruction or agreement with source text.

Each emitted token records its step, generated-prefix length and hash, source
input hash, raw next-token-logit hash and selected token. The final token list
reconstructs every prefix without quadratic prefix-array storage. CPU float32
execution uses one thread, evaluation mode and disabled gradients. Parameters,
buffers, existing gradients, storage, RNG, thread settings and training modes
are preserved.

The [comparison runtime](../../ipfs_datasets_py/logic/formalization/autoencoder/gte_decoder_source_comparison.py)
loads independent original donor models from their raw checkpoint bodies and
loads available student generations privately. It checks all 26 inherited
student tensors and requires disjoint parameter storage across models. Each
native source enters the primary adapter once per forward; the auxiliary
branch receives its learned connector output from the same shared condition.
The original 8D donor independently receives its original raw 8D latent.

## Parent admission and saved replay

The [command](../../scripts/ops/autoencoder/evaluate_gte_decoder_sources.py)
admits a completed [aligned-start training](gte_aligned_interface_training.md)
parent and two raw donor files before loading tensor libraries. Its
[standard-library parent reader](../../scripts/ops/autoencoder/gte_source_evaluation_parent.py)
reconstructs the original native and affine-aligned parent closures, their
implementation inventories, saved inspections and dependency accounting.
Trained parents additionally bind the four-interface checkpoint, separate
report, checkpoint inspection and historical reload receipt. Historical
numerical metadata remains metadata until a fresh numerical execution occurs.

Unavailable parents still provide authenticated original donor inputs. The
raw checkpoint file hashes must match the initialization's external donor
pins; copied student heads cannot impersonate independently loaded donors.
Output directories cannot overlap any input, preserved implementation root
or prior output namespace. Inputs and implementations are rechecked before
execution and before completion.

Saved comparison inspection reconstructs source/model-state bindings, fixed
budgets, strict scores and complete row accounting without numerical imports.
It explicitly does not authenticate numerical execution. The command then
loads fresh private models and repeats the entire comparison, requiring exact
agreement of tokens, per-step logits, model/input hashes and scores with the
saved report. The completion manifest is written last.

## Command and current baseline

The [configuration](../../configs/autoencoders/gte_decoder_source_evaluation_v1.json)
pins the existing unavailable training parent and both original checkpoints,
selects all 60 primary plus two auxiliary rows, and uses `evaluate`. Run from
the repository root with the existing local Torch installation and a fresh
output directory:

~~~bash
python scripts/ops/autoencoder/evaluate_gte_decoder_sources.py \
  --config configs/autoencoders/gte_decoder_source_evaluation_v1.json \
  --expected-config-sha256 13b65fbf97a02005b9880ab9e0caf2cfb7c0fdd132324f144a5b48a08becc009 \
  --output-directory /home/barberb/lift_coding/artifacts/gte-decoder-source-evaluation-preparation-20261002/reproduction-01 \
  --threads 1 --cpu-time-limit-seconds 600
~~~

`prepare` admits the same inputs and saves a plan, inspection and summary with
no numerical model. `evaluate` adds a resource receipt, comparison, comparison
inspection and exact numerical replay. Both modes publish a completion
manifest after verification. Exit 0 means completed unqualified evidence;
it does not mean quality gates passed. Exit 2 means invalid input or execution
failure, and no completion manifest is published.

The [completed baseline](../../../../artifacts/gte-decoder-source-evaluation-preparation-20261002/run-01/manifest.json)

record the current original-donor regression. Native evaluation coverage is
