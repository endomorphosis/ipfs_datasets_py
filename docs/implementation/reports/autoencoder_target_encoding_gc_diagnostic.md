# Archived target encoding GC diagnostic

Status: diagnostic complete; **no production GC policy changed**. Across two counterbalanced pairs, pausing cyclic GC during tagged encoding and JSON serialization reduced the cleanup-inclusive codec interval to a median **1.898585 seconds** for six archived targets. The normal interval was **4.109540 seconds before cleanup**, or **4.180257 seconds including the same cleanup**. This establishes a bounded codec opportunity, not a native target-producer or end-to-end speed claim.

The [audited summary](evidence/autoencoder_control_plane_plan/encoding-gc-codec-diagnostic-20260925.json) binds the four receipts, input artifact, ordered target inventory, source identities and timing calculations. The [harness](../../../scripts/ops/encoding_gc_codec_diagnostic_20260925.py) has SHA-256 `c440e0c7b8239ceae03248403896adbe6204312ff3092b4afe65fc04b362a6c8`. Each mode ran in a fresh native `/usr/bin/python3` process, sequentially: normal/paused, then paused/normal. CPython 3.12.3, zlib 1.3, offline model settings, disabled CUDA and lazy Ergo installation, and one CPU/bridge worker were identical across all four runs. No target generation, training, model loading or publication ran.

The candidate total was 2.210955 seconds lower than the normal interval even when only the candidate pays for cleanup: a 53.8% reduction within this diagnostic. Against normal mode with the same cleanup included, the reduction was 2.281672 seconds, or 54.6%. Both pairs agree on the direction; two pairs on one fixed bundle do not establish corpus-wide performance or concurrency behavior.

The timed encoding interval contains `_encode`, `_json`, and release of the temporary tagged object graph. The candidate pauses cyclic collection only over that interval, restores the original policy in `finally`, and performs one explicit generation-2 collection while the current target remains live. Its reported total includes restoration, any collection triggered by restoration, bookkeeping and that explicit collection. Normal mode reports both its interval without this extension and its total with the same forced collection. Ordinary bundle writing does not force these collections.

Each target is read, expanded, strictly parsed and decoded independently. `_validate_target` uses its exact archived sample ID, status and embedded configuration. Hydration and a full **pre-encoding collection are outside the encoding measurement**; the latter ages the graph and deliberately equalizes starting state. That differs from the native writer's state immediately after bridge generation. Median hydration setup was 4.483423/4.511333 seconds in normal/paused mode, and the starting collections added 0.072041/0.072904 seconds. Strict validation was separately recorded at 0.672375/0.670980 seconds and normal-GC compression at 1.046490/1.048022 seconds. Those phases, input verification, source guards and parity hashing are not hidden inside the primary comparison.

Normal encoding made 7,026/635/37 collections by generation in each run. Callback-observed collection time was 2.247297 and 2.274584 seconds, including 2.031034 and 2.058364 seconds in generation 2. Paused encoding made no collections. JSON serialization remained near 0.90 seconds and temporary-graph release near 0.11 seconds in both modes. Six explicit terminal collections cost a median 0.070667 seconds normally and 0.072593 seconds after pausing. All observed encoding/restoration/terminal collection reclaimed-object and uncollectable counts were zero. The reduction was therefore not merely shifted into the immediate cleanup measured here. Original enabled state, thresholds `[700, 10, 10]`, debug state and callback list were restored in every run.

The input is the [historically qualified hydration experiment's](evidence/autoencoder_control_plane_plan/target-hydration-gc-native-20260925.json) bundle, SHA-256 `40b16465f121169d607a315876a0a395a545d6482f1b29e79fe5c2dca150f0b7`: 12,846,582 bytes overall, six ready targets, and 212,381,851 expanded bytes. The largest expanded shard is 65,235,489 bytes. The harness enforces 64 MiB per shard and 256 MiB total expanded bounds and retains at most one complete target at a time. These are encoded-byte bounds, not RSS bounds.

All four receipts report exact equality of every full canonical re-encoded target and every zlib-level-6 compressed shard. Streaming the reconstructed shard bodies after the original header/manifest reproduced the complete original artifact digest. The audit independently checked the receipt and harness identities, manifest identity and order, embedded configuration, whole bundle, compressed and expanded digests, full zlib recompression bytes, and reconstructed bundle SHA. It also recomputed timing totals and GC deltas. It did not repeat target hydration or canonical re-encoding: those full-byte checks are recorded by the frozen harness in each run. Original manifest bytes were reused, so sample-payload recomputation and writer publication were not exercised.

Every before/after package manifest was identical, and all four runs shared the same 7,710-file manifest, SHA-256 `c01be25eaf7e1e87e9a10b6866cb3334f11f489a70c918be21f3d60678011958`. The archived embedded configuration remained unchanged. Seven package paths, including the parser, differ between that archived producer and the diagnostic source tree. Consequently these are archived-format checks; stable diagnostic sources do not requalify the old bundle for current training.

Process high-water RSS was effectively unchanged: maximum 711,036 KiB normally and 710,960 KiB with pausing, approximately 694 MiB. These values include imports, hydration, encoding and earlier records. On the largest target, the recorded process high-water rose from approximately 638,000 KiB before encoding to approximately 711,000 KiB afterward. Hydration substantially contributes to memory use, but the final peak cannot be attributed solely to hydration or treated as isolated encoding memory. No RSS bound or memory reduction is established.

The [failed-start note](evidence/autoencoder_control_plane_plan/encoding-gc-codec-failed-start-20260925.json) preserves the initial normal launch's `IsADirectoryError`, before package imports or measurement. The source scanner was corrected to match the cold profiler: reject symlinks or paths resolving outside the package, and hash only files, skipping directories named with a `.py` suffix. The note is attributed to the root agent's observed tool output, not a retained raw traceback. Twelve earlier synthetic helper smoke cases checked success and exact encode/JSON exception propagation with enabled/disabled initial GC states; they do not qualify native target production.

The [cold preparation profile](autoencoder_cold_target_profile.md) remains the guide to priority: its modal adapter cost about 50.9 seconds, whereas encoding GC accounted for about 4.3 seconds. That profile used a different target bundle and a post-generation GC state; its timings cannot be substituted into this experiment or combined into a projected production speedup. A production encoding pause would first need exact native-input eligibility, a useful graph bound before allocation, restoration and exception guards, and fresh native qualification. The writer accepts arbitrary mappings and a record generator, so this result does not justify pausing GC around unconstrained generation or the whole writer.

No parser, target format, validation, source configuration or admission behavior changed. No Hugging Face publication or Quack transport claim is made. The Constitution remains unformalized and no Constitution span is marked `roundtrip_ok`. Only `lake build <Lib>` constitutes a Lean admit.
