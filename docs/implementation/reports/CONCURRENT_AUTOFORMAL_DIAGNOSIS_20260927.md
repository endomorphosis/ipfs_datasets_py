## Why earlier proposals were rejected

Historical R5/R6 goal context was present: 2,321 estimated input tokens under the unchanged 4,096 limit, `truncated=false`, no omissions, and all required fields. Those tasks were explicitly deterministic-only and made zero provider calls. Their compiler-quality and decompiler head scales were zero. They did not ask a coding provider to repair the compiler and then lose that instruction in the goal database.

R6 correctly rolled back all nine proposals: six regressed legal-IR metrics, and three family proposals had no objective gain. A focused reproduction found a class-support discontinuity: adding a sixth zero-logit class to a five-class uniform baseline increases cross-entropy by `ln(6/5) = 0.182321556794`, even without a useful parameter update. This explains a concrete regression mechanism, not necessarily every earlier failure.

A second defect allowed a target deadline to be swallowed by broad adapter `except Exception` handlers. The owner cancellation now derives from `BaseException` and is caught explicitly by its owner; ordinary adapter errors and the explicit timeout fallback still work. Missing/timeout targets remain failures, never successful bridge targets. Acceptance thresholds were not relaxed. [Reproduction and qualification](evidence/concurrent-autoformal-diagnosis-20260927/qualification/optimizer-fix/canonical-application-receipt.json)

The fresh proposal lane materialized its complete prompt and 17 verified artifact references in a native DuckDB goal and review-only task. Stored goal/task prompts exactly matched the actual request. The task was not claimed or completed by the implementation daemon; actual training execution is established separately by the native supervisor worker receipts.

One request reached the existing local model server: temperature 0.0, seed 0, maximum response 768 tokens, JSON-object response format, and an actual token allowance of 1,303 input + 768 output + 64 margin = 2,135, under the same 4,096 effective limit. No context window, installation or weights were changed.

The returned 2,226-byte proposal was incomplete JSON and therefore failed before application. Review also found an unauthorized compiler key, a self-recursive parser helper and repeated assignments. Rejection was appropriate. The prompt producer did have a concrete context defect: its `_OBJECT_TOKEN_RE` anchor captured only the opening `re.compile(` line instead of the whole multiline assignment. That is an incomplete source selection, not goal-database truncation. A future proposal should include complete AST-delimited definitions and preserve the same bounded prompt and acceptance rules. No proposed code was applied, imported or promoted.
