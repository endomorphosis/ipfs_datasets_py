# Bounded target hydration GC deferral

Status: implemented and qualified on four bounded native jobs, **default off**. Median owner-dispatched job time fell from **23.64 to 19.73 seconds (16.5%)**, with identical evaluation results and optimizer rejection decisions. The gain comes from target hydration; the training loop and bridge evaluation did not become faster. No target format, parser, target payload, loss, or admission rule changes in this slice.

The [native comparison receipt](evidence/autoencoder_control_plane_plan/target-hydration-gc-native-20260925.json) and [reproducible harness](../../../scripts/ops/legal_ir/benchmark_target_hydration_gc.py) bind one freshly prepared six-target bundle to four independent combined Arrow/sparse jobs. The order is normal/deferred/deferred/normal, each in a fresh spawned process through the ordinary local DuckDB owner. Three training and three validation samples come from the same frozen source-bound U.S. Code selection used by earlier qualification; they are not a corpus-wide canary.

Both pairs reduced complete-job time (23.54 → 19.76 seconds and 23.75 → 19.71 seconds). Hydration fell 57.4%; explicit cleanup cost 0.095–0.106 seconds and is included. Native normal hydration made 8,400/763/25 collections by generation, while deferred hydration made only its one explicit generation-2 collection. Both reclaimed the same 30 cyclic objects. Memory remained similar at roughly 1.68 GiB high-water RSS. This is two pairs on one six-target bundle, not a statistical or corpus-scale speed guarantee, and it does not qualify a higher concurrency level.

That fresh bundle was then reused by the four jobs; these evaluations are not cold target-generation measurements. OS cache was uncontrolled. Native captured triples/full target graph bytes were not separately re-encoded in this harness; the codec diagnostic below provides that narrower exact-byte check. The median codec total fell 64.15%, a 2.789× ratio. Normal mode performed 8,372 generation-0, 761 generation-1, and 36 generation-2 collections in each loop. Generation-2 scans alone consumed 4.342–4.394 seconds; all collected and uncollectable counters were zero. Paused mode had no collections during hydration. Its immediate post-enable generation-0 collection cost another 25–29 ms, already included in total time, followed by the explicit full collection. The measured reduction was therefore not merely deferred into the first post-load collection.

The input was the [ontology-observation native run's](evidence/autoencoder_control_plane_plan/ontology-observation-native-20260925.json) six-target bundle: 12,843,560 bytes overall, including 11,746,781 compressed target bytes, expanding to 212,314,592 bytes. That preparation reported all five bridges for each target. The codec experiment decoded existing targets; it did not evaluate those bridges again. The current parser differs from the archived producer. The experiment retained the embedded configuration unchanged and claims archived-format validation only, not current producer qualification. It preloaded all six raw byte strings, unlike the worker's sequential shard handling. Peak measured RSS was roughly 1.1 GiB; parity re-encoding later raised process peak RSS further. Two pairs, callback instrumentation, and uncontrolled OS cache limit generalization.

[The coordinator](../../../ipfs_datasets_py/optimizers/logic_theorem_optimizer/autoencoder_training_coordinator.py) exposes `run_training_jobs(..., defer_target_hydration_gc=False)`. Enabling it requires the native executor and native worker function; non-booleans and injected execution are rejected before jobs or registry state are consumed. Native dispatch selects a private worker entry. Ordinary public worker calls and public bundle loaders retain their existing GC policy.

[The worker's `_hydrate_shared_targets`](../../../ipfs_datasets_py/optimizers/logic_theorem_optimizer/autoencoder_training_worker.py) rechecks eligibility at hydration. Deferral requires an exact native `TargetBundle`, CPython, a spawned child process, the main thread, exactly one Python thread, enabled GC, no GC debug flags, and no GC callbacks. The verified bundle's total referenced uncompressed tagged-JSON size must be positive and at most **256 MiB**. This is an encoded-payload cap, **not an RSS bound**; Python containers and already-loaded model state can require substantially more memory. Ineligible requests use ordinary hydration and report the reason.

The helper pauses only cyclic collection around the unchanged `targets_for` call. Artifact/configuration binding, requested sample identities, compressed/expanded digests, strict tagged decoding, complete target validation, and source-text checks remain in [the bundle loader](../../../ipfs_datasets_py/optimizers/logic_theorem_optimizer/legal_ir_target_bundle.py). Fresh mutable target containers are still produced. The helper restores GC enabled state in `finally`; hydration failures propagate without a forced collection that could replace the original failure. After successful hydration it performs `gc.collect(2)` before training and restores enabled state again even if collection raises. Thresholds are not modified.

Worker receipts record requested/applied policy, skip reason, encoded-byte cap, GC state/thresholds and generation statistics, hydration time, explicit collection time, and total helper time. `target_hydration_gc.total_seconds` and outer `target_hydration_seconds` include restoration and cleanup. Use these totals for comparisons: `collection_seconds` covers the explicit collection and can exclude an automatic collection immediately after GC is enabled. Existing memory observations provide process RSS context.

This changes less infrastructure than a new prepared evaluator-payload protocol or a broader Arrow representation. It preserves the existing codec and independent hydration, saving about 3.91 seconds per owner-managed job in this comparison. It does not remove first-time parsing, validation, target memory, or ontology capture. A reduced evaluator representation would introduce new derivation and trust obligations: the owner currently verifies artifact bytes, while each worker validates full requested target semantics. [Ontology capture reuse](autoencoder_ontology_capture_reuse_design.md) still needs reliable transitive completion evidence and mutation/dependency guards; Arrow transport alone does not eliminate those computations. The next useful measurements are cold target production and retained target memory across larger bounded batches, before expanding numeric mapping or adopting a new payload protocol.
