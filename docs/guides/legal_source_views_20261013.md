# Versioned legal source views and producer declarations

This additive stage improves the evidence available before legal spans become
entity, definition, relationship, or doctrine proposals. It does not admit legal
claims or qualify model outputs. The completed source-custody campaign and its
paragraph-view selectors remain historical artifacts with their original hashes.

`legal_official_document_views` uses the upstream strict declared-encoding/BOM
decoder and a bounded balanced-markup parser. The new v2 view retains metadata,
headings, paragraphs, table cells, source credits, field comments, notes, and
footnotes in DOM order. Unicode and UTF8 offsets refer to the new normalized
document text. They are not raw HTML offsets, original producer offsets, or
interchangeable with v1 selectors. The heading profile explicitly records the
ASCII hyphen/en-dash rendering of a literal section token; it creates no cache
identity aliases. Declared note fields take precedence over statutory-looking
markup within notes. Unsupported markup, encoding, ambiguity, or bounds produce
explicit refusals rather than partial successful views.

`legal_source_view_inventory` regenerates the complete provenance and new view
reports under independent full-report pins, then enumerates every overlapping
literal occurrence in every comparison document with the same literal legal ID.
It retains all physical cache records, repeated records, missing documents,
zero-match results, and ambiguity. Each occurrence records intersections with
observed markup regions. Even a single match leaves the selected occurrence and
governing source binding empty. Publisher URLs and independently selected 2024
snapshots do not establish which edition the producer used.

`legal_producer_lineage` verifies a separate recorded declaration chain: physical
cache record to an independently retained producer JSON receipt, its compressed
artifact container, and explicitly declared physical parent Parquet rows. The
full parent repository revision must be present in the producer receipt; a short
cache revision is never expanded by prefix matching. Parent file SHA256, byte
count, footer population, requested row ordinals, and complete row hashes are
independent inputs. Bounded incremental reads retain every selected row and
column. The output distinguishes local declaration replay from proof of actual
historical model execution, an original character occurrence, legal authority,
and official edition correspondence.

The retained twenty-row population comprises eight paired cache rows and twelve
flat evidence rows from span-cache revision
`765176c6db79ba65c1697c21dead43666350b730`. Ten independently selected GovInfo
snapshots contain 284,111 raw HTML bytes. The new view extracts all ten documents
and 1,476 normalized blocks, including the previously unsupported section
16:410oo-2 and previously refused 26:141 document. The unchanged v1 reports still
extract eight documents. An independent compatibility audit confirms that the
upstream decoder change leaves all ten historical v1 reports byte-for-byte
equivalent after canonical serialization.

The new inventory records 22 literal occurrences in nine physical rows, compared
with 20 occurrences in seven rows under the paragraph view. The two additional
matches are note fragments in 16:410oo-2 and 26:141. Two other header fragments
still do not match exactly, and eight authored examples have no supplied
comparison document. All occurrences remain unselected.

The training frontier also advanced upstream. The 2026-10-13 actor-ranking run
completed 32 updates of actor CE plus compatible-span hinge loss, with 130 active
trainable actor scalars and 34 frozen original split tensors. Independent
upstream recounts report no complete-IR gains or losses against frozen CE in
nine paired authored panels. Training remains 153/168 complete IR; fresh
development and test each remain 0/36. These were previously exposed authored
engineering examples, and eight statutory examples were unscored. The hinge
experiment is complete and must no longer be proposed as an unrun experiment.
Its proposed successor is actor-feature adaptation, followed by separately
measured modality/presence and candidate-coverage work. There is no default model
promotion or qualified latent semantics. The immutable release is
`Publicus/legal-ir-autoencoder` revision
`3c430bdb412a6bd0871f813a944dfec5b2f4c8e9`. Current public metadata identifies
the checkpoint as an ordinary Git blob, without an LFS SHA256 descriptor. This
campaign reads metadata and recorded evaluations, not checkpoint weights.

The corresponding native supervisor board has three independent qualification
lanes: document views, complete occurrence inventories, and producer lineage plus
detached actor-ranking contracts. It uses the existing shared resource scheduler
and the inherited serialized Git checkout transactions. The original sixty-task
plan remains unchanged and its broader tasks remain partially accepted.

After these bounded contracts are qualified, the next work is to support a
bounded page-level reader or obtain an independently authenticated smaller
parent transport, then replay the six requested original physical rows. The next semantic work is to
reconstruct quality-controlled statutory spans from pinned source bodies with
explicit context and original occurrence coordinates; build an independently
reviewed gold population; and create typed entity/definition/relationship
proposals with edition, scope, and dependency closure. Doctrine composition must
retain unresolved conflicts and review obligations. Lean4 admission requires
explicit theorem statements, dependency manifests, proof artifacts, and actual
kernel checks. None of those semantic or proof gates is discharged by this
source-view stage.
