# Literal parent text views and candidate span reconstruction

This stage starts from six page-qualified physical rows of the original parent
Parquet file. It preserves their exact string fields before candidate occurrences
or sentence boundaries are reconstructed. Physical custody and literal coordinate
accuracy do not establish governing legal text, official-source correspondence,
context closure, semantic correctness, training permission, or Lean4 admission.

The parent is `justicedao/ipfs_uscode` revision
`5016b86a273ce5e4ffd066c5ae9f5fe494dd417e`, path
`uscode_parquet/laws.parquet`, SHA256
`4d26df1e3814279e4b4df3af0e454b4f64fc89a81879db926989862b6ad7d8b8`.
Its page-qualified selected-row report retains ordinals 2673, 2674, 2675, 2676,
2677, and 2681, with all 45 original fields and independent complete-row hashes.
The selected population is six rows from a 60,077-row file, not full-parent or
full-cache coverage. The completed page-replay artifacts remain separate inputs.

The fixed page reader verifies the complete file hash, footer, schema, physical
geometry, and all 423 page headers. Preflight inspects optional CRC declarations;
CRC values are checked, when present, for page bodies actually decoded. The six
rows require 90 page bodies totaling 60,389,242 decoded bytes. These bounded
parser contracts do not claim an absolute process memory peak or kernel quota.

All six `text` fields are already flattened plain strings, each on one line,
without HTML markup. Their character counts are 3491, 1920, 3851, 3162, 2870,
and 4936; UTF8 byte counts are 3526, 1945, 3892, 3190, 2889, and 5015. They mix
U.S.C. metadata, heading text, statutory language, source credits, and notes.
Original HTML or DOM region boundaries cannot be recovered from these strings.
An edition written in the text remains an observation rather than an authenticated
governing-edition binding.

The producer's `subsections_json`, `raw_json`, and empty `parser_warnings` also
remain observations. The retained rows show contamination of parsed subsections
by source credits or historical notes, including a subsection replaced by notes.
Those fields are preserved losslessly and cannot serve as segmentation gold.

`legal_parent_text_views.prepare_parent_text_views` consumes the complete selected
report together with its independently retained FULL canonical hash, parent
descriptor/hash, preflight/hash, and complete ordered row ordinal/hash population.
It regenerates the selected report through the fixed page reader before retaining
views. Optional `page_limits` and view `limits` can lower finite bounds. A missing,
empty, or nontext field remains an explicit unresolved physical row.

The top-level `selected_rows_report` retains all original row fields once.
Each `views` entry binds its physical ordinal, row-group geometry and complete
row hash. Its `text_view` contains the exact `text` value, text hash, character and
UTF8 lengths, a portable immutable file/row/field identity, and a versioned
coordinate origin. Changing a source revision or physical occurrence changes that
identity; merely copying the same immutable file to another local path does not.
The complete report still binds the distinct local custody report and its FULL
independent pin.

The view profile performs no whitespace, Unicode, case, punctuation, identifier,
or heading normalization. Half-open character ranges count Unicode code points in
the original decoded Parquet field. Half-open byte ranges count UTF8 bytes of that
same field. They are neither Parquet-file byte offsets nor original-HTML offsets.

Every view has one `entire_text_unclassified` region covering all its characters.
All literal matches of the declared `law_name` and fixed note-header phrases are
retained as marker candidates, including repeated and overlapping presentations.
A unique heading match does not select a governing body or establish a credit,
note, metadata, or statutory boundary. Marker kinds and ranges are observations;
legal region roles remain unresolved.

`parent_text_views_report_sha256` hashes the FULL report, including its internal
seal. `validate_parent_text_views` requires that external pin and regenerates the
complete report from the trusted parent inputs. Self-resealing changed text,
geometry, marker ranges, authority flags, order, or population cannot substitute
for this replay.

The public `exact_parent_text_occurrences` similarly requires the FULL view report
and complete trusted parent inputs. It returns every literal overlap for an exact
physical ordinal, with independent character/UTF8 geometry, text/hash, immutable
row identity, and an occurrence seal. It never chooses the first or sole match.
Fixed downstream owners may validate a complete bounded population once before
using internal coordinate helpers; those helpers do not confer source authority.

View limits bound rows, individual and aggregate field bytes, complete marker and
occurrence populations, selected literal bytes, observation bytes, and full report
bytes. Bounds are enforced incrementally and refuse oversized complete populations
instead of truncating them. Repeated physical rows and identical mentions remain
distinct observations.

The cache-to-parent stage must retain all twenty supplied physical cache records,
including duplicates and unresolved links. Its eight previously verified local
producer declarations concern report/parent identity only. The twelve unresolved
records remain in the denominator. Exact substring occurrences, including zero,
single, and multiple matches, add observations without accepting a governing
source occurrence or historical model invocation.

Candidate sentence reconstruction starts from the six complete literal parent
views rather than treating diagnostic cache fragments as statutory gold. Lexical
boundary proposals must preserve every character, all metadata and notes, repeated
presentations, and marker intersections. Body roles, exceptions, cross-references,
definitions, temporal applicability, and context remain unresolved until separately
authenticated and reviewed. A lexical partition cannot make a span eligible for
autoformalization by itself.

Focused view tests cover complete row custody, exact Unicode/UTF8 ranges and
overlaps, immutable occurrence/revision identity, portability, marker ambiguity,
unavailable fields, externally pinned full regeneration, and refusal before partial
retention. Native qualification and actual reconstruction results are recorded by
the campaign completion artifact; this guide does not substitute for that receipt.

Next work is to compare reconstructed parent occurrences with independently
acquired official source views, preserve source-region and edition ambiguities,
resolve the six context dependency slots, and record reviewed statutory gold.
Only those separately qualified inputs can feed typed entity, definition and
relationship proposals, conflict-preserving doctrine composition, and separately
checked Lean4 statements and proofs. Accepted graphs, training and model promotion
remain outside this stage.
