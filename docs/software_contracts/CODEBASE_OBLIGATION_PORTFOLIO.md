# Captured CodebaseIR obligation portfolios

Status: implemented, pending final native joined qualification. Twelve closed
graph/identity/domain controls pass under the frozen source bytes. Earlier
individual Lean, Rocq, Isabelle, Z3, CVC5 and TLC smoke runs succeeded, but their
new wrapper source hashes were not retained. Their exact generated source,
bundles, native executable identities and process/kernel receipts are preserved
as historical component evidence only. They do not qualify the final joined
AND/OR orchestrator. Recent joined attempts were refused by actual CPU, memory
headroom and disk admission policies; those policies were not weakened.
See [retained qualification evidence](evidence/codebase-obligation-portfolio-20261002/qualification.json).

This opt-in local profile executes a typed AND/OR obligation graph for one or
two captured Python integer-offset functions. It composes the existing native
source, ProgramIR, contract, VC, SMT, kernel and TLA owners with the supervisor's
shared repository resource reservation. It does not introduce a source head,
proof head, persistent proof cache, task-completion rule or model checkpoint.

The datasets owners are `codebase_family_lowering`, `codebase_family_execution`
and `codebase_obligation_graph`. The consumer is
`ipfs_accelerate_py.agent_supervisor.proof.codebase_obligation_portfolio`.
The public consumer requires the actual repository reservation, an exact native
source head, a complete immutable CodebaseIR semantic manifest, selected paths,
finite inputs and explicit sealed native tools.

## The exact semantic claim

The native closed Python profile supplies captured source correspondence and
the declared integer-offset contract. Its assumptions remain attached: callers
provide exact built-in integers, arithmetic is the mathematical unbounded model,
and loading, rebinding, concurrency, allocation failure and asynchronous
interruption are outside modeled execution. An annotation is not a runtime
type check.

For each source unit, the graph requires three obligations:

- An OR choice of Lean, Rocq and Isabelle kernel reconstructions of the exact
  mathematical integer relation. Each branch also contains the same Z3/CVC5
  query as non-authoritative candidate evidence. The existing
  `VerificationPortfolio` selector requires a kernel reconstruction before
  reporting mathematical success. Conflicting outcomes quarantine the node.
- A TLC invariant check over an explicit finite stuttering state model with the
  same input/output relation. The reviewed lowering removes the generic
  compiler's proposed progress property, retains its finite-step disclosure,
  and asserts no liveness claim.
- A separate Lean-checked, one-way restriction of the mathematical relation to
  precisely the finite inputs selected for the state model. This bridge depends
  on a successful mathematical premise. The finite check never proves the
  unbounded relation or arbitrary cross-family equivalence.

The root AND additionally requires final native source-head, ignore/configuration
policy and immutable semantic-manifest replay. Changing source invalidates all
dependent results for current use; earlier native receipts remain historical
records of their exact captured mathematical model. Unsupported inventory units
remain in the manifest denominator. Selecting one produces an explicit
unsupported result.

The profile permits 1–16 sorted, distinct exact integer inputs with a span at
most 64. It supports only the existing closed single-function syntax.
TLC constants and reachable additions must have absolute value at most
2^31−1, matching the qualified concrete integer range; the independent kernel
formula still quantifies over mathematical integers. TLC's upstream
[IntValue implementation](https://github.com/tlaplus/tlaplus/blob/master/tlatools/org.lamport.tlatools/src/tlc2/value/impl/IntValue.java)
stores a Java integer; the declared bound also prevents intermediate addition
overflow for the selected reachable states. Native
kernel success when the body differs from its declared contract establishes a
specific integer counterexample, not the original contract. No report asserts
arbitrary Python-runtime correctness or authorizes task completion.

## Execution, identity and bounds

Independent source nodes and compatible native attempts use a bounded executor
with at most two concurrent workers. The actual supervisor reservation feeds
the existing shared datasets resource scheduler. Each native attempt acquires
a further child lease before launching the existing qualified process runner.
No separate CPU/RAM allocator is introduced.

Run-local single-flight deduplicates only identical complete bundle, tool,
implementation, source-head, operation and execution-bound requests within that
invocation. Changed contracts or source versions cannot share a flight. There
is no cross-run positive-verdict reuse. Every native receipt, generated input
file identity, stdin identity, resource binding and process observation is
retained in the bounded report.

Tool paths are explicit; this profile performs no installation or download.
Before and after execution it verifies selected launcher/executable and declared
runtime artifact bytes, plus the direct Python producer inventory. Installed
tools, ambient shared libraries and transitive compiled theorem imports are
trusted dependencies; their authenticity and entire transitive closure are not
attested. Native proof receipt metadata does not remove those assumptions.

Lean/Rocq/TLC use an 8 GiB virtual-address allowance, while Isabelle uses 64 GiB
for the bundled Poly/ML allocator. Measured RSS ceilings remain 512 MiB for
Lean/Rocq, 768 MiB for TLC and 1536 MiB for Isabelle; Z3/CVC5 use 256 MiB. Virtual
address space is distinct from resident-memory admission. RSS enforcement is
sampled by the existing process owner, not a cgroup guarantee.

Isabelle2025-2 uses its actual `process_theories` command in an isolated HOL
session. A private workspace settings directory selects one thread, SerialGC,
a 256 MiB JVM heap and a 768 MiB Poly/ML heap. No installed or user settings are
modified. The exact generated wrapper/settings identities accompany the
observations. TLC is restricted to one worker. Each attempt has a bounded
deadline and output/workspace limits; the entire request remains under its
parent's deadline and native pressure admission.

Optional cancellation applies only to redundant Rocq/Isabelle branches. It
cannot cancel the required Lean bridge or final source validation. Parent
cancellation or timeout cannot produce success. No per-parent reserved
validation capacity is invented: required validation runs after bounded native
work drains, subject to the existing global scheduler's validation reservation.
