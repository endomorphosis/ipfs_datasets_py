# Explicit duration occurrences, scopes and clocks

`legal_ir.temporal_bindings` adds an opt-in join between the existing canonical candidate, its caller-supplied qualified interpretation, the existing normative scope declaration, exact occurrence maps and separately supplied clock declarations. `legal_ir.duration_bound_qualified` validates that complete join before calling the unchanged qualified emitter. It preserves the emitter's original output and retains the additional binding evidence separately.

This closes a structural provenance gap: the old qualified emitter bound temporal qualifiers to whole-source identity and facet indexes. The new join records each temporal atom's canonical rule/index, scope rule, exact leaf path, occurrence ID, source or context origin, character interval and UTF-8 interval. Repeated identical text remains distinct when the caller supplies exact geometry. Missing, extra, swapped, shared or overlapping ownership is refused. No literal search chooses an occurrence, and duration-looking actor, object, condition or exception text cannot supply a temporal occurrence.

The clock declaration retains its own ID, provenance scope, exact anchored bytes and explicit kind, quantity, unit, domain, origin and endpoint choices. Its geometry establishes integrity, not that those words legally authorize the clock. Clock fields must exactly match the unchanged interpretation with exact types: a boolean cannot substitute for a quantity, and an integer cannot substitute for a boolean endpoint flag. The initial profile supports local `within` and `for at least` day/hour durations, discrete natural-number time and an explicit caller-supplied evaluation origin. Calendar dates, business-day arithmetic, event-relative origins, unresolved coverage, binders, shared attachments and nested scope remain unsupported. They are refused rather than flattened or repaired.

The structural binding owner can preserve declared context. The lowering consumer currently requires `none_required` context because the unchanged qualified emitter has no qualified context-transport profile. Both operations preserve complete inputs and expected content digests. Neither operation authenticates a physical statutory artifact, a reviewer or an encoder checkpoint; those remain separate custody and review boundaries. The supplied source/scope/clock declarations are not statutory gold or supervised targets.

Use `prepare_duration_bindings(candidate, interpretation, scope_request, scope_declaration, occurrence_bindings, clock_declarations, **expected_pins)` followed by `validate_duration_bindings(report, *original_inputs, **expected_pins)`. The four expected pins bind the candidate, interpretation, complete scope input and sealed scope declaration. These are canonical content digests, distinct from physical file hashes. `prepare_duration_bound_qualified(report, *original_inputs, expected_report_sha256=..., **expected_pins)` also requires the complete externally pinned report. Its matching validator replays the binding, original native preparation and complete output. Unfilled interpretation skeletons remain insufficient for lowering.

Import-time producer pins are rechecked before scope validation or lazy native import and after preparation. A changed file cannot label stale imported code with a new producer identity. Every result keeps semantic, review, training, proof, family-promotion and compiler authority false, with zero supervision masks. Prepared native code is not a successful `lake build legal`, a statutory fidelity result, or qualification of every registered logic family. Existing decoder objectives, selector policies, emitters and default routes are unchanged.

Current namespace-based inert validation passed 417 distinct cases, with two existing real-Lake tests disabled. This comprises the final 138 new boundary cases, 222 unchanged scope/native/corpus cases and 57 unchanged training-recipe cases. The first run's 133 pre-fix boundary cases are preserved as history and excluded from the current count. Tests cover distinct repeated literals, exchanged IDs and leaf paths, role overlap, complete maps, source/context substitution, Unicode offsets, exact supported clocks, original native-output equality and changed-producer refusals before downstream calls. Numerical imports and network/process calls are denied except the two retained exact import controls; top-level plugin startup and real compiler execution are not qualified by these runs.
