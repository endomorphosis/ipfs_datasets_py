# Explicit duration occurrence, scope and clock custody

The new `legal_ir.temporal_bindings` boundary joins the existing canonical candidate and `legal-canonical-qualified-interpretation/v1` formats to a complete `canonical_statement_scope` declaration. It is opt-in and additive. No old decoder, trainer, parser, registry, emitter, scope owner or statutory review gate is changed.

The current qualified owner previously retained whole-source identity and canonical temporal indices but did not establish exact qualifier occurrence geometry. The new boundary requires a caller to supply every duration mapping. A mapping names the canonical rule and temporal index, actual scope rule ID, exact temporal leaf path and occurrence ID, original source/context duration anchor, and an independently supplied clock ID. No substring search, clock inference, context truncation or facet repair occurs.

Both duration anchors and clock declaration anchors retain the complete origin text SHA256, Unicode character half-open bounds, UTF8 byte half-open bounds and exact text. UTF8 offsets are recomputed from the complete chosen source or context. Caller clock anchors establish source custody for a declaration; they do not show that the words authorize that clock, attest an actual evaluation event, or resolve source meaning. `declaration_id` is a caller declaration identity, not an authenticated reviewer identity.

The initial transport profile accepts local flat `within N days/hours` and `for at least N days/hours` literals, quantities from 1 through 1,000,000, and explicit `discrete_nat` clocks with `caller_supplied_evaluation_time` and inclusive lower/upper endpoints. Choices must exactly agree, including Python JSON scalar types, with the unchanged interpretation. Unsupported, null, calendar, business-day, event-relative and real-time origins are refused. No days-to-hours conversion occurs. Clock quantity and units are a caller convention, not elapsed civil time.

Rules must align in their declared order, and every canonical core and qualifier symbol must match its actual scope-owned occurrence. Conditions and exceptions retain their original roles even if their text resembles a duration. Identical temporal text at distinct physical source occurrences remains distinct. Missing, extra, duplicated, swapped or misordered duration maps fail the entire join. Reusing one temporal occurrence across rules, overlapping temporal geometry or overlap with a non-temporal role is refused by this initial local profile. Shared statements, nested qualifiers and binders require a separate supported owner rather than flattening.

`prepare_duration_bindings(candidate, interpretation, scope_request, scope_declaration, occurrence_bindings, clock_declarations, ...)` requires separate externally expected content SHA256 pins for the candidate, interpretation, complete scope input and complete sealed scope declaration. Its report retains all six detached inputs and explicit clocks, derived joins, counts and validation pins. These are canonical JSON content digests, not physical file digests. Strict parsing rejects duplicate object keys, floats, nonfinite numbers, foreign Python objects and non-UTF8 bytes. Reports have bounded bytes, depth and node counts. Replay uses separately retained original inputs; re-signing a changed report does not repair a failed replay.

The transport report deliberately leaves native interpretation grammar unassessed. Existing mapping/formula digests and non-temporal expression declarations are preserved, and remain subject to the old qualified owner. Complete coverage is caller-declared source geometry, not independently established semantic completeness. Statutory packet, submission, artifact and reviewer custody remain with their separate owners. All training masks are zero and all semantic, qualification, statutory, model, encoder, proof and Lake flags are false. A zero-duration report records an explicit zero count and does not invent a deadline from actor, object or qualifier text.

The companion `legal_ir.duration_bound_qualified` consumer replays the complete externally pinned report before lazily importing the unchanged `legal_canonical_qualified` owner. It accepts only `none_required` context and direct source occurrence geometry. Context-bound reports remain inert transport; they cannot silently lower through a no-context profile. The consumer calls the original `prepare_canonical_qualified(candidate, interpretation)` without editing either input and retains its complete byte-equivalent output alongside the complete binding report. Existing native predicate/expression, mapping/formula and duration-activation refusals remain active. Producer endpoint identities include old owners and both additive boundaries and are checked before/after preparation.

Successful consumer preparation records emitted native/Lean source preparation. It requires `lake build legal` in a separate backend step and claims no compiler execution, source fidelity, family qualification, semantic equivalence or legal truth. It does not promote these outputs into TDFOL, DCEC, temporal/event/cognitive registries, training gold or proof supervision. Consumers must retain statutory custody and independently review legal ownership and clock meaning before any future admission decision. Additive binding/scope and wrapper source endpoints are fenced against identities observed at import; endpoint substitutions are rejected before native import and checked again after preparation. These observations do not authenticate executable memory or continuous custody.

The authored tests exercise exact repeated occurrences across roles and across two separate rules; Unicode and combining marks; context-origin custody; integer/bool type swaps; repeated, missing and exchanged maps; source-consistent unsupported fragments/dates; role-overlap refusal; report tampering; context and changed-producer refusal before native import; preservation of old native output; and native validation remaining with its existing owner. These are engineering controls, not US Code reference labels or model accuracy evidence. This implementation agent ran AST parsing only. The root coordinator owns inert tests, independent review and integration. The initial 355-pass/2-skip root observation predates the imported-producer finding; all four exact pre-fix source/test files were preserved with their previous SHA256 identities before the narrow fence and five additional controls. Final test claims must use the root's affected-file rerun and exclude superseded cases from aggregate denominators.

Future work must separately support source-to-context coordinate custody, shared/nested scopes, binder-sensitive ownership, actual temporal event origins and reviewed clock conventions. Each needs an explicit profile and evidence owner. This boundary provides a replayable prerequisite for that work; it does not establish those capabilities.
